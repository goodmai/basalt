# GemmaServer Development Guidelines

## Project Context

**Product:** Local LLM inference server for Apple Silicon  
**Stack:** Swift 6, MLX, Hummingbird 2.x, Swift Concurrency (actors)  
**Architecture:** Dual-interface server (MCP stdio + REST HTTP) with shared actor-based orchestrator

## Core Principles

### 1. Code Organization & File Size
- **Keep files under 300-500 lines** (excluding integration tests)
- **Single Responsibility Principle**: One actor/class = one clear purpose
- **Extract when growing**: If a file exceeds 500 lines, split into:
  - Protocol definitions → separate file
  - Extensions → `TypeName+Extension.swift`
  - Nested types → separate files if complex
  - Helper functions → `TypeNameHelpers.swift`
- **Exception**: Integration test files can be longer due to setup/teardown/fixtures

```swift
// ❌ BAD: 800-line god class
actor ModelOrchestrator {
    // model loading
    // inference
    // streaming
    // metrics
    // caching
    // error handling
    // logging
}

// ✅ GOOD: Split responsibilities
actor ModelOrchestrator {
    private let loader: ModelLoader
    private let engine: InferenceEngine
    private let metrics: MetricsCollector
    private let cache: ModelCache
}

// Separate files:
// - ModelLoader.swift (150 lines)
// - InferenceEngine.swift (200 lines)
// - MetricsCollector.swift (100 lines)
// - ModelCache.swift (180 lines)
```

### 2. Swift 6 Strict Concurrency
- **Always use actors** for shared mutable state
- **Typed throws** (`throws(GemmaServerError)`) for all error paths
- **Sendable conformance** for all DTOs crossing isolation boundaries
- Pattern: `actor ModelOrchestratorActor` → single source of truth, FIFO queue guaranteed

### 3. Pattern Matching Over Conditionals
```swift
// ✅ GOOD: Exhaustive pattern matching
let action: DownloadAction = switch (existingSize, totalSize) {
case (let s, let t) where s > 0 && t > 0 && s == t: .skip
case (let s, let t) where s > 0 && s < t: .resume(from: s)
default: .startNew
}

// ❌ BAD: Nested if-else
if existingSize > 0 && totalSize > 0 && existingSize == totalSize {
    action = .skip
} else if existingSize > 0 && existingSize < totalSize {
    action = .resume(from: existingSize)
} else {
    action = .startNew
}
```

### 4. Performance-First
- **Avoid O(n²) string concatenation**: Use `[String]` + `.joined()` for streaming text
- **Minimize allocations**: Reuse `ByteBuffer`, avoid intermediate `Data` copies
- **Profile before optimizing**: Use `ContinuousClock` for timing, `Memory.snapshot()` for RAM

### 5. Error Handling
```swift
// Typed throws enum (Swift 6)
public enum GemmaServerError: Error, Sendable, LocalizedError {
    case modelNotFound(identifier: String)
    case inferenceHardwareFailure(reason: String)
    
    public var httpStatus: Int {
        switch self {
        case .modelNotFound: return 404
        case .inferenceHardwareFailure: return 503
        }
    }
}

// Usage
func load(modelPath: String) async throws(GemmaServerError) {
    guard FileManager.default.fileExists(atPath: modelPath) else {
        throw .modelNotFound(identifier: modelPath)
    }
}
```

## Development Workflow (TDD → Implementation → Integration → Profile → Commit)

### Phase 1: TDD (Test-Driven Development)
1. **Write failing test first** using Swift Testing (`@Test`, `#expect`)
2. **Define interface** (protocol/actor methods) before implementation
3. **Use mocks** for external dependencies (e.g., `MockInferenceEngine`)

```swift
@Test("generate before load throws inferenceHardwareFailure")
func generateBeforeLoad() async throws {
    let engine = MockInferenceEngine()
    let orch = ModelOrchestratorActor(engine: engine)
    
    await #expect(throws: GemmaServerError.self) {
        _ = try await orch.generate(request: .init(prompt: "Hello"))
    }
}
```

### Phase 2: Implementation
1. **Implement minimal code** to pass the test
2. **Follow Swift 6 concurrency rules** (no data races)
3. **Use pattern matching** for state machines and enums
4. **Avoid premature optimization** — correctness first

### Phase 3: Integration Testing
1. **Test actor interactions** (orchestrator ↔ engine ↔ server)
2. **Test concurrent access** (50+ parallel requests)
3. **Test error propagation** across isolation boundaries

```swift
@Test("intensive concurrency: 50 parallel requests")
func intensiveConcurrency() async throws {
    let orch = ModelOrchestratorActor(engine: MockInferenceEngine())
    try await orch.loadModel(path: "model")
    
    try await withThrowingTaskGroup(of: GenerationResponse.self) { group in
        for i in 1...50 {
            group.addTask {
                try await orch.generate(request: .init(prompt: "Prompt \(i)"))
            }
        }
        var count = 0
        for try await _ in group { count += 1 }
        #expect(count == 50)
    }
}
```

### Phase 4: Profiling & Benchmarking
1. **Run `PerformanceBenchmark`** with `--iterations 10`
2. **Measure TPS, TTFT, memory** for each change
3. **Compare before/after** — regression = revert
4. **Document results** in commit message

```bash
swift run -c release PerformanceBenchmark \
  --model mlx-community/Qwen3.5-4B-4bit \
  --iterations 10 \
  --tokens 100
```

### Phase 5: Debug & Fix
1. **Use `print()` sparingly** — prefer structured logging
2. **Check actor isolation** if seeing data races
3. **Verify Sendable conformance** for all cross-actor types
4. **Test edge cases**: empty input, OOM, network timeout

## Logging Best Practices

### Structured Logging (Not print)
```swift
// ❌ BAD: Unstructured print statements
print("Loading model")
print("Error: \(error)")
print("TPS: \(tps)")

// ✅ GOOD: Structured logging with context
import os

extension Logger {
    static let modelOrchestrator = Logger(
        subsystem: "com.gemmaserver.core",
        category: "ModelOrchestrator"
    )
    static let inference = Logger(
        subsystem: "com.gemmaserver.core",
        category: "InferenceEngine"
    )
    static let api = Logger(
        subsystem: "com.gemmaserver.api",
        category: "RESTServer"
    )
}

// Usage in code
actor ModelOrchestratorActor {
    private let logger = Logger.modelOrchestrator
    
    func loadModel(path: String) async throws {
        logger.info("Loading model", metadata: [
            "path": "\(path)",
            "timestamp": "\(Date())"
        ])
        
        do {
            try await engine.load(modelPath: path)
            logger.notice("Model loaded successfully", metadata: [
                "path": "\(path)",
                "duration": "\(duration.inSeconds)s"
            ])
        } catch {
            logger.error("Model load failed", metadata: [
                "path": "\(path)",
                "error": "\(error.localizedDescription)",
                "errorType": "\(type(of: error))"
            ])
            throw error
        }
    }
}
```

### Log Levels
- **`.debug`**: Detailed diagnostic info (disabled in production)
- **`.info`**: General informational messages (startup, shutdown, config)
- **`.notice`**: Significant events (model loaded, request completed)
- **`.warning`**: Potential issues (slow response, high memory)
- **`.error`**: Errors that need attention (failed requests, crashes)
- **`.fault`**: Critical failures (system-level errors)

### What to Log
```swift
// ✅ ALWAYS log:
// 1. Entry/exit of major operations
logger.info("Starting model download", metadata: ["repoId": "\(repoId)"])
logger.notice("Model download completed", metadata: [
    "repoId": "\(repoId)",
    "duration": "\(duration)s",
    "size": "\(sizeBytes) bytes"
])

// 2. All errors with full context
logger.error("Inference failed", metadata: [
    "requestId": "\(requestId)",
    "modelId": "\(modelId)",
    "prompt": "\(prompt.prefix(50))...",
    "error": "\(error)",
    "stackTrace": "\(Thread.callStackSymbols)"
])

// 3. Performance metrics
logger.notice("Generation completed", metadata: [
    "requestId": "\(requestId)",
    "tps": "\(tps)",
    "ttft": "\(ttft)s",
    "tokens": "\(tokens)",
    "memoryMB": "\(memoryMB)"
])

// 4. State changes
logger.info("Model state changed", metadata: [
    "from": "\(oldState)",
    "to": "\(newState)",
    "reason": "\(reason)"
])

// 5. External API calls
logger.debug("HuggingFace API request", metadata: [
    "url": "\(url)",
    "method": "GET",
    "headers": "\(headers)"
])
```

### Defect Detection Through Logs
**Goal**: Logs should allow identifying defect and defective module in <5 minutes.

```swift
// ✅ GOOD: Logs enable quick defect isolation
// Log output:
// [ModelOrchestrator] INFO: Loading model path=/models/qwen3.5-4b
// [InferenceEngine] INFO: Initializing MLX container
// [InferenceEngine] ERROR: MLX initialization failed error=Metal device not found module=InferenceEngine
// [ModelOrchestrator] ERROR: Model load failed path=/models/qwen3.5-4b error=inferenceHardwareFailure module=ModelOrchestrator

// From logs, we know:
// - Defect: Metal device not found
// - Defective module: InferenceEngine
// - Root cause: GPU not available
// - Time to identify: <1 minute
```

### Log Metadata Standards
**Always include:**
- `module`: Component name (e.g., "ModelOrchestrator", "RESTServer")
- `operation`: What's being done (e.g., "loadModel", "generate", "download")
- `requestId`: Unique ID for tracing requests across components
- `timestamp`: When the event occurred (auto-added by Logger)
- `duration`: How long operation took (for completed operations)
- `error`: Full error description (for failures)
- `errorType`: Swift type of error (for debugging)

```swift
// Standard log format
logger.error("Operation failed", metadata: [
    "module": "ModelOrchestrator",
    "operation": "generate",
    "requestId": "\(requestId)",
    "modelId": "\(modelId)",
    "error": "\(error.localizedDescription)",
    "errorType": "\(type(of: error))",
    "duration": "\(duration.inSeconds)s"
])
```

## Architecture Patterns

### Actor-Based Orchestration
```swift
// Single source of truth — all requests FIFO-queued
public actor ModelOrchestratorActor {
    private let engine: any InferenceEngine
    
    public func generate(request: GenerationRequest) async throws(GemmaServerError) -> GenerationResponse {
        let validated = try request.validated(defaultMaxTokens: maxTokens)
        return try await engine.generate(request: validated)
    }
}
```

### Streaming with AsyncStream
```swift
public func generateStream(request: GenerationRequest) async throws(GemmaServerError) -> AsyncStream<StreamChunk> {
    let mlxStream = try await container.generate(input: lmInput, parameters: params)
    var chunks: [String] = []  // ✅ Avoid O(n²) concatenation
    
    return AsyncStream<StreamChunk> {
        for await generation in mlxStream {
            switch generation {
            case .chunk(let text):
                chunks.append(text)
                return .text(text)
            case .info(let info):
                return .metadata(buildResponse(chunks.joined(), info))
            }
        }
        return nil
    }
}
```

### Typed DTOs (Codable + Sendable)
```swift
public struct GenerationRequest: Codable, Sendable {
    public let prompt: String
    public let maxTokens: Int?
    public let temperature: Double?
    
    public func validated(defaultMaxTokens: Int) throws(GemmaServerError) -> GenerationRequest {
        guard !prompt.isEmpty else {
            throw .invalidRequestStructure(details: "prompt must not be empty")
        }
        let maxT = maxTokens ?? defaultMaxTokens
        guard 1...65_536 ~= maxT else {
            throw .contextLengthExceeded(maxTokens: 65_536, requested: maxT)
        }
        return GenerationRequest(prompt: prompt, maxTokens: maxT, temperature: temperature)
    }
}
```

### Test Fixtures & Helpers
- **Extract common setup** into fixtures to avoid duplication
- **Keep fixtures under 100 lines** — split if growing
- **Use `@Suite` with shared state** for related tests
- **Fixtures location**: `Tests/Fixtures/` or inline for simple cases

```swift
// ✅ GOOD: Shared fixture for model tests
@Suite("Model Loading Tests")
struct ModelLoadingTests {
    let fixture = ModelTestFixture()
    
    @Test("load valid model succeeds")
    func loadValidModel() async throws {
        let orch = fixture.createOrchestrator()
        try await orch.loadModel(path: fixture.validModelPath)
        #expect(await orch.isLoaded)
    }
    
    @Test("load invalid model throws")
    func loadInvalidModel() async throws {
        let orch = fixture.createOrchestrator()
        await #expect(throws: GemmaServerError.self) {
            try await orch.loadModel(path: fixture.invalidModelPath)
        }
    }
}

// Fixture in separate file: Tests/Fixtures/ModelTestFixture.swift
struct ModelTestFixture {
    let validModelPath = "/tmp/test-model"
    let invalidModelPath = "/tmp/nonexistent"
    
    func createOrchestrator() -> ModelOrchestratorActor {
        ModelOrchestratorActor(engine: MockInferenceEngine())
    }
    
    func createMockEngine(shouldFail: Bool = false) -> MockInferenceEngine {
        let engine = MockInferenceEngine()
        engine.shouldFailOnLoad = shouldFail
        return engine
    }
}
```

## Common Pitfalls

### ❌ Don't: Create god classes over 500 lines
```swift
// BAD: 1200-line file doing everything
actor ModelOrchestrator {
    // 200 lines: model loading
    // 300 lines: inference logic
    // 200 lines: streaming
    // 150 lines: metrics collection
    // 150 lines: caching
    // 200 lines: error handling
}
```

### ✅ Do: Split into focused components
```swift
// ModelOrchestrator.swift (180 lines)
actor ModelOrchestrator {
    private let loader: ModelLoader
    private let engine: InferenceEngine
    private let metrics: MetricsCollector
    private let cache: ModelCache
}

// ModelLoader.swift (150 lines)
// InferenceEngine.swift (200 lines)
// MetricsCollector.swift (100 lines)
// ModelCache.swift (180 lines)
```

### ❌ Don't: Capture mutable state in @Sendable closures
```swift
// BAD: data race
var counter = 0
Task { @Sendable in
    counter += 1  // ⚠️ Mutation of captured var in concurrent code
}
```

### ✅ Do: Use actors for shared state
```swift
actor Counter {
    private var value = 0
    func increment() { value += 1 }
}
```

### ❌ Don't: Block actor with synchronous I/O
```swift
actor BadActor {
    func load() {
        let data = try! Data(contentsOf: url)  // ⚠️ Blocks actor queue
    }
}
```

### ✅ Do: Use async I/O
```swift
actor GoodActor {
    func load() async throws {
        let (data, _) = try await URLSession.shared.data(from: url)
    }
}
```

## When to Split a File

**Triggers for splitting:**
1. File exceeds 500 lines
2. Multiple responsibilities in one type
3. Scrolling required to understand the type
4. Difficult to locate specific functionality
5. Test file has duplicate setup code (extract fixture)

**How to split:**
```swift
// Before: ModelOrchestrator.swift (800 lines)
actor ModelOrchestrator {
    // loading logic
    // inference logic
    // caching logic
    // metrics logic
}

// After: Split into 4 files
// ModelOrchestrator.swift (150 lines) — coordination only
actor ModelOrchestrator {
    private let loader: ModelLoader
    private let engine: InferenceEngine
    private let cache: ModelCache
    private let metrics: MetricsCollector

// ModelLoader.swift (180 lines)
```
