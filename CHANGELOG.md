## 0.9.0 — 2026-11-03

### Upgrading from 0.8.0
- mlx-swift-lm now comes from the fork `goodmai/mlx-swift-lm`, pinned by revision (`42737a5`, branch `feat/mtp-prefix-reuse`): upstream `1830ae4f` plus one commit per feature in this release. Those are MambaCache multi-checkpoint rewind for MTP blocks deeper than 2, adaptive MTP depth, the fused LFM2 MoE and Gemma 4 router, the public staged KV-round API, and MTP prefix reuse (#207, #241, #221, #161). The checkpoint and KV-round APIs are `package`-level upstream, and upstream's agent policy rules out upstream PRs for these changes for now, so they live in the fork. Moving back toward an upstream release stays with #102. Builds re-resolve the package from the fork URL, so a mirror or a pinned `Package.resolved` needs updating.
- `serve --mtp-block N` (also `PerformanceBenchmark --mtp-block`) sets the largest MTP verify round: the target's own token plus up to N−1 drafted ones. It defaults to 4 and is adaptive: each request starts at one drafted token per round, goes one deeper after four fully accepted rounds in a row, and drops back to one on any rejection (#207, #241). `--mtp-block 2` is exactly 0.8.0's behaviour.
- `--mtp` requests now reuse the prompt cache like every other request, instead of prefilling the whole prompt on every turn (#207). MTP requests still take no hybrid anchors and no disk restore, and the 8192-token prompt limit stays. The drafter prefixes kept for reuse (at most 4, about 30 MB each at 8k tokens on Bonsai 2) are not counted in the prompt-cache byte budget.
- `--speculative-lookup` now also runs on sliding-window models: Gemma 4 12B and the 26B-A4B MoE (#161). On 26B-A4B it nearly doubles code edits but costs 3–6% on prose and reasoning, because each verify forward loads experts for the extra tokens; leave lookup off there if your traffic is mostly prose. Grammar jump-forward (`--grammar-jump-forward`) goes through the same guard, so it now runs on Gemma 4 too. Recurrent hybrids with expert routing (LFM2.5 MoE, Qwen3.5 MoE) stay on plain decoding.
- The memory coordinator is on by default (#220). Under macOS memory pressure it shrinks the MLX allocator cache and the prompt-cache budget, evicting LRU branches. At critical pressure it refuses prompts of 8192+ tokens, or any prompt with no room left, with 503 `Retry-After: 30` (MCP `-32013`). `serve --no-memory-coordinator` keeps 0.8.0's fixed limits.
- Hybrid models snapshot recurrent state at message boundaries by default, `serve --hybrid-anchors 8` (#219). The anchors are charged to the prompt-cache budget (about 50 MB each on Ornith-1.5-9B); `--hybrid-anchors 0` turns them off.
- New opt-ins that change nothing unless used: the `X-Basalt-Cache-Key` header gives a client its own prompt-cache namespace (#88), and `serve --batch-slots N` (default 1, off) batches decode across concurrent requests (#240). The body field `prompt_cache_key` stays ignored.
- With `--router-params`, `"auto"` routing now escalates to the cloud model after local turns fail: repetition, a server-default length cut, or a repaired or rejected tool call (#176). The state is persisted to `router-bias.json` next to the cost file. With β = 0 routing is bit-for-bit the 0.8.0 scorer, and nothing is recorded without `--router-params`.
- `models inspect` and `models check --deep` refuse a safetensors header with gaps or overlaps between `data_offsets`, which the format forbids (#227).

### Performance
- MTP drafting on Qwen3.5-family targets, three steps (#207, #241). All numbers are Bonsai 2 27B (`Youssofal/Ternary-Bonsai-2-27B-MTPLX-Optimized-Speed`) on an M4 Pro 24 GB, release, T=0.7, 300 tokens, 3 runs per cell.
  - Deeper blocks (#261): the fork's `MambaCache` keeps a speculative checkpoint after every draft position, and the GatedDeltaNet forward verifies the block in segments. A rejection at any depth restores that exact state, so the result is bit-exact without a custom kernel, and the rewind limit goes from 1 to 7 tokens (Qwen3.5 only). A fixed deep block wins on code and loses on prose, which the adaptive default below fixes.
  - Adaptive depth, the new default (#263): code 27.1 tok/s, prose 20.7, reasoning 24.9, against 20.9 / 19.9 / 19.8 with MTP off (1.30×, 1.04×, 1.26×) and 26.0 / 20.8 / 24.9 at the old fixed block 2. Static depth 4 gave 28.9 on code but lost 29% on prose and 12% on reasoning. Drafts accepted: code 630 of 651, prose 336 of 612, reasoning 486 of 597. Greedy output at blocks 2, 3 and 4 is byte-identical to plain decoding.
  - Prompt-cache reuse (#266): the stored prefix is leased as for any request, and the head runs from the reused length up to the snapshot boundary in one forward. The drafter's prefix (cache, position and the carried hidden row) is kept per namespace, cut one token before the target's, so the next turn can change that token. If no matching drafter prefix exists, the request prefills in full as before. On a 1,149-token second turn, 1,140 tokens come from the cache, and TTFT drops from 12.53 s to 0.75 s; decode is 21.5 against 20.3 tok/s. Drafts accepted (39 of 41) and the greedy text are identical to a full prefill.
- Prompt lookup on Gemma 4 (#161): on a cache with a `RotatingKVCache`, each verify forward runs as a staged KV round that commits only the accepted drafts plus one, instead of trimming a ring that may have wrapped. Measured on `gemma-4-12B-it-qat-4bit` (M4 Pro, release, T=0.7, two passes): code edits 3.45×/3.62× (18.7 → 64.6 tok/s, rounds verified across the 1,024-token window), prose 1.02×/0.99×, reasoning 1.04×/1.03×. On `gemma-4-26B-A4B-it-qat-4bit`: code 1.97×, prose 0.96–0.97×, reasoning 0.94–0.95×. Code and reasoning output equal plain decoding. Prose parts from it at a temperature-0 near-tie that the multi-token verify resolves the other way, the same verify numerics as on every lookup model; before the window wraps, the staged path is byte-identical to the trim path.
- Speculative gating on recurrent hybrids (#241): after a rejection, the replay forward also samples the next token, so a rejected round costs no extra forward (#257). The stricter hybrid-only acceptance bar added alongside it no longer paid off, so `DraftBackoff` is back to one `≥ 25%` rule for every model (#259). Reasoning on Ornith-1.5-9B at T=0.7 went from 0.96× of plain decoding to 0.99×. Code edits stay at 2.41–2.46×, and prose at 1.00× (no drafts).
- Fused MoE router top-k for single-row decode on LFM2 MoE and Gemma 4 (#221). These models now use mlx-swift-lm's existing `fusedRouterTopK` kernel (through a new `sigmoidBiasRouterTopK` for LFM2's selection-only bias), cutting the dispatches after the gate from 12 to 5 on LFM2 and from 7 to 5 on Gemma 4. Output is bitwise identical (10,000 random rows, ties included), so it is always on; prefill and batched decode keep the chain. The router had been 7.0% of a decode step on LFM2.5-8B-A1B, 8.1% on LFM2.5-24B-A2B and 1.8% on Gemma 4 26B-A4B. At T=0.7, B=1: +5–10% on both LFM2.5 models (e.g. 24B-A2B prose 104.5 → 115.3 tok/s) and +1–2% on Gemma 4 26B-A4B.
- Recurrent anchors on hybrid models, `serve --hybrid-anchors N` (default 8, 0 off) (#219): while prefilling, the engine also snapshots the recurrent state (Gated DeltaNet, Mamba, LFM2 conv) at message boundaries the chat template renders (start of an assistant turn, after a tool result, after a reasoning block), so a request whose middle was rewritten (a dropped `<think>` block, a truncated tool result) resumes from the deepest anchor before the edit instead of prefilling from the start. Anchors are ordinary prompt-cache nodes, charged to its budget, at most N per conversation, at least 512 tokens apart, and reported in `/api/v1/stats` (`hybridAnchors`, `hybridAnchorBytes`); sliding-window and pure-attention models take none. Measured on Ornith-1.5-9B with a 34K-token agent trace: dropping the reasoning of turn 3 of 6 now reuses 12 965 tokens instead of 0 (111.4 → 68.9 s, 1.62×), of turn 5 23 673 instead of 12 968 (80.7 → 34.5 s, 2.34×); appending a turn is not slower (24.3 → 20.5 s); output is identical to a cold prefill. Everything after the edit still prefills, so the gain grows with how late the edit is; 12 anchors held 618 MB on Ornith.
- Continuous batching of the decode phase, `serve --batch-slots N` (default 1, off; needs `--max-concurrent` 2 or more) (#240): concurrent generations decode together in one `[B,1]` forward through a `BatchKVCache` with per-row left padding and RoPE offsets. Each row samples with its own processor (one `argMax` for an all-greedy batch), joins after its own B=1 prefill and leaves on EOS, `max_tokens` or cancellation without disturbing the others. Batching applies only when every cache layer is plain `KVCacheSimple` and the request has no grammar or forced tool, prompt lookup, MTP, CacheBlend, `--kv-bits`, zones or media, and while memory pressure is below tight (#220). Hybrid and sliding-window rows diverged from their solo decode in a batch, so those models keep the serialized path. Measured on Llama-3.1-8B-Instruct-4bit, M4 Pro, 512-token greedy answers: 4 concurrent requests total 113.4 tok/s against 58.3 with batching off (2.10× a single request); a lone request is 2.8% slower (52.4 against 53.9 tok/s). While a request with a cache key decodes, its prompt KV is held twice.

### Memory
- `MemoryCoordinator` (#220) reads `kern.memorystatus_vm_pressure_level` every second and on each admission, and steps through relaxed → tight (warning: allocator cache 25% plus `Memory.clearCache()`, prompt-cache budget 25%) → critical (12.5%, cache 0, long prompts refused and the KV budget capped by free memory). After pressure ends it steps back through restoring (50%), one step per 30 s of normal pressure. Steps apply at admission, at completion and while idle, never mid-decode, so on a long request the reaction waits for it to end (69–87 s on 27B). Under an incompressible 8 GB allocation, Qwen3.8-27B-3bit swapped out 611 064 pages instead of 1 141 478 (−46%), with a GPU peak of 13.59 GB instead of 16.98. Gemma 4 26B-A4B under 4 GB: 207 968 instead of 538 936 (−61%), with a peak of 15.79 GB instead of 17.31. A 1500-token generation took 274.1 s against 277.2 s on 27B, and 52.9 s against 54.2 s on 26B-A4B. With one request and nothing cached to give back, it changes nothing measurable. `/api/v1/stats` and `serve --stats` gain a `memory` block: pressure, step, limits, used/budget prompt-cache bytes, evictions and refusals.

### Models
- `basalt models check --deep <repo>` checks that `serve` will load a Hub repo and render its chat template, before any weight is downloaded (#227). It fetches the configs and templates plus each shard's safetensors header through two `Range` requests, aborting any response that is not a 206. It builds the model shape-only from `config.json` with lazy zero tensors and runs the loader's own `sanitize`, quantization rewrite and `verify: .all`, then renders the template with a system prompt, a tool, a tool call and its result. Missing, unexpected and mismatched keys (bit-width mismatches included) and template errors are listed; `--json` gives `{"fit", "deep"}`, and the exit code is non-zero on any failure. From a cold cache: 179–446 KB fetched, 2.4–3.4 s and at most 94 MB RSS for Gemma 4 12B, Qwen3.8-27B and Qwen3-4B. Kimi-Linear-48B is refused for its `model_type` and its template. Hub repo ids only: no local paths, `--quant`, gated repos, dtype checks or EOS-token check.
- Gemma 4 prompt-cache hits equal a prefill cut at the same points bitwise (max abs diff 0.0 over 13.4k tokens and over a 12-turn session on Gemma 4 12B) (#247). Their distance from a cold one-phase prefill (max 0.60–2.33) is no larger than the one-phase prefill's own dependence on chunk size (2.53 between 512- and 256-token chunks). A greedy token that flips on a cache hit is a near-tie, not a cache bug.

### API
- `X-Basalt-Cache-Key: <name>` on any generation endpoint (`/v1/chat/completions`, `/v1/responses`, `/v1/messages`, `/v1/generate`, `/api/v1/generate[/stream]`) keeps the request's prompt cache in a tree of its own, apart from the shared tree and from other keys, within the same byte budget (#88). Empty or longer than 256 bytes is ignored; service requests still bypass the cache; `prompt_cache_key` in the body stays ignored so per-thread Codex keys keep sharing the system prompt.
- `POST /v1/embeddings` (OpenAI shape: `input` string, list or token ids, `encoding_format` float or base64, `dimensions` only on Matryoshka models) and `POST /v1/rerank` (Cohere/Jina shape: `query`, `documents`, `top_n`, `return_documents`), backed by mlx-swift-lm's MLXEmbedders and MLXRerankers, with `serve --embedding-model` and `--rerank-model` (#178). Both models stay resident next to the chat model, are counted in its memory budget, sit behind the same API key, host and body guards, and run under the generation gate, so an embedding batch never shares the GPU with a decode step. A chat checkpoint passed as an embedder is refused at startup. Measured on an M4 Pro with the official `openai` 3.19.2 SDK: bge-small-en-v1.5 at 229–299 texts/s and Qwen3-Embedding-0.6B at 20 texts/s (batches of 32 × ~240 tokens); known pairs rank correctly with both embedders and with Qwen3-Reranker-0.6B and jina-reranker-v3; chat decode with an idle embedder is unchanged (86–89 vs 89 tok/s), but a large indexing job on Qwen3-Embedding slows a concurrent chat to 0.56–0.72×, because each batch holds the gate.
- `/api/v1/stats` reports `draftTokens` and `acceptedDraftTokens` summed across requests, and `serve --stats` prints `Drafts: A of D accepted`; both are absent until some request has drafted (#241).
- Session-log `response` records carry `tool_call_repairs` and `tool_call_rejections`, which `GenerationResponse` also exposes as `toolCallRepairs` / `toolCallRejections` (#176).

### Cloud routing
- Outcome-driven escalation bias for the Bradley–Terry router (#176). For each local model `id@revision` and bucket (`toolUse` or `general`), the router keeps a bias β and scores `σ(logit + β)`. A failing local turn adds η = 0.1 and a clean one subtracts η/4. β is clamped to [0, 0.5] and halves every hour, so three failing turns escalate a prompt sitting 0.05 below θ = 0.5. Error turns and service requests are not counted. `basalt cloud cost` prints the decayed β, and `/api/v1/stats` reports it as `routingBias`. The defaults are provisional until a replay over real session logs. The `toolUse` bucket is counted, but it moves no serve traffic yet, because tool requests are not sent to the cloud.

### Experimental
- DRY repetition penalty and XTC sampling, request fields `dry_multiplier`, `dry_base`, `dry_allowed_length`, `dry_sequence_breakers`, `xtc_threshold`, `xtc_probability` (camelCase on `/api/v1/generate`), accepted only with `serve --experimental-samplers` and refused with 400 otherwise (#177). DRY penalizes the token that would extend a sequence the model already wrote (its own output only: with the prompt in its history it broke verbatim code edits); XTC removes the likeliest tokens with probability p at T > 0. Measured on an M4 Pro: decode speed unchanged (1.02–1.035×), JSON constraints still win, code edits still parse on Qwen3-4B and Bonsai 2 27B. Not an anti-loop tool: on a 2-bit Qwen3.8, DRY turned a verbatim loop that `RepetitionGuard` stops into one with corrupted numbers that runs to `max_tokens`; on models that do not loop it changed nothing.

### Fixes
- Hybrid `qwen3_5` models no longer leak memory on every load and generation (#251). The fused GatedDeltaNet projection was captured as a compiled-trace constant that outlives the compiled function (ml-explore/mlx#3932), so every `switch_model` or reload lost memory: +652 MB per round on Ornith-1.5-9B, and 1690 → 3909 MB over 3 rounds on Qwen3.8-27B. Both now hold 0 MB after 4 rounds; the fix is upstream mlx-swift-lm #631 (`1830ae4f`), which the fork is based on. Decode speed is 47.2 against 43.5 tok/s on Ornith-9B, and within noise on Qwen3.8-27B.
- A prefill now finishes on its own thread (`Stream.defaultStream.synchronize()`) before the decode worker takes over, so one generation's work never sits in two thread-local command encoders (#214). That is the pattern in the `~CommandEncoder()` crash reports, though the crash itself has not been reproduced. The wait counts toward TTFT. On the zoned-KV and no-prompt-cache paths, a cancelled request (client gone, preemption) used to keep decoding until `max_tokens`; it now stops.
- Untrusted Hub input (#213): a file name from the HF API such as `../../x` is skipped instead of being written outside the model directory, and an invalid repo id throws `HFError.invalidRepoId` instead of crashing. An `mlx_lm_extra_tensors.mtp_file` outside the model directory is ignored (#204).
- Text-only `qwen3_5_text` targets (flat `config.json`) now get an MTP drafter (#204).
- An unreadable cloud usage file used to reset spend to zero and be overwritten on the next save, which disabled the cloud budget cap. It is now moved aside as `<name>.corrupt-<time>` with a line on stderr; a corrupt cloud config, a failed log write and a failed harness `INDEX.md` write are reported too (#213).
- Clipboard input over 64 KB no longer hangs basalt: `pbpaste` stdin is written on its own thread while stdout and stderr are read (#213).

### Build and CI
- The xcode-toolchain action could select `Xcode_*_Release_Candidate.app`: under `pipefail`, `grep -q` exited early and `printf` got EPIPE (#238). Wall-clock guards in the drain, gate, MCP-shutdown and redactor tests now have load headroom; under load, 0 of 6 suite runs failed, against 4 of 6 before.
- Tiny test models for every family come from one `TinyModel.make` factory. A new kernel or decode path must ship a parity test against the stock MLX graph on a tiny fixture, with no mocked engine below `BasaltServer` (`CONTRIBUTING.md`) (#228).
- `scripts/speculative_lookup_bench.swift` measures code, prose and reasoning at T=0.7 only, with Qwen3-4B and Ornith-1.5-9B as default models (#241).

## 0.8.0 — 2026-11-01

### Upgrading from 0.7.0
- With `--max-concurrent` above 1, a request that fits the KV room alone but not next to the requests already running is refused with 503 `Retry-After: 1` instead of being prefilled into an out-of-memory (#204). With one request at a time nothing changes.
- Building and running Basalt (Homebrew included; Homebrew 7+ requires `brew trust goodmai/basalt`) now targets macOS 27+ with Xcode 27.0+ (Swift 6.4) (#185), unlocking the full Swift 6.4 standard library directly without back-deployment fallbacks. SwiftPM 6.4 uses Swift Build as the default build backend, so build artifact paths come from `swift build [-c release] --show-bin-path` instead of hard-coded `.build/debug` and `.build/release` directories.
- `--rate-limit` is now per client instead of server-wide (#62): each virtual key, bearer token, `x-api-key` or client address gets its own bucket, with `--rate-burst` (default `min(rate, 10)`, `0` off) for the instantaneous burst. The table holds at most 4096 clients and evicts idle ones first.
- A streaming request that fails before its first token (uncached model, failed switch) now gets its HTTP status and a provider error body instead of `200` plus an SSE error event (#76). Errors on every endpoint use the provider's envelope (`/v1/messages` Anthropic, `/v1/*` OpenAI, `/api/v1/*` native), 429 and 503 carry `Retry-After`, and 401 carries `WWW-Authenticate: Bearer`.
- MCP tools are now `basalt_generate`, `basalt_status` and `basalt_add_knowledge`; the `gemma_*` names stay as aliases (#64). Config and profile files live in `~/.basalt/`, read from `~/.gem/` when the new file is missing, and new API keys start with `basalt_`. `GemLogger`, `GemLogLevel` and `GemCLI` are typealiases of their `Basalt*` names.

### Performance
- `serve --mtp` drafts with a model's multi-token-prediction head (#204): `mtp.safetensors` as MTPLX packs ship it (or `mlx_lm_extra_tensors.mtp_file`, or `mtp/weights.safetensors`) loads into mlx-swift-lm's Qwen3.5 MTP drafter, and each round verifies one drafted token in the same forward as the next. Drafts are argmax and every emitted token is the target's own sample, so output is exact at any temperature, top-p, top-k or min-p. Used for requests without a JSON constraint, speculative lookup, `--kv-bits` or `--kv-zones`, with prompts up to 8192 tokens, and without prompt-cache reuse (the prompt is prefilled in one forward, which TTFT counts); Qwen3.5-family targets only. On Ternary Bonsai 2 27B (the MTPLX pack, Qwen3.8-27B's head grafted onto Prism's ternary trunk), a greedy code edit runs 26.3 tok/s against 21.2 plain on an M4 Pro, α = 0.98, with identical output; corpus numbers are in #204.
- Opt-in grammar jump-forward for constrained decoding, `serve --grammar-jump-forward` or `grammar_jump_forward` per request (#175): tokens the JSON grammar forces are fed in one multi-token forward instead of one step each, respecting `max_tokens` inside a forced span. Off by default with output identical to 0.7.0; not used with `--kv-bits`, `--kv-zones`, rotating caches (Gemma 4) or hybrids with expert routing.
- Prompt lookup backs off on low-yield drafts (#172): a round counts as profitable only with 3+ accepted tokens or a 25% acceptance rate, and the draft limit shrinks to 2 after a miss and grows with acceptances, so reasoning-style text on dense models no longer runs 17-token verifies that accept one.
- Prompt-lookup drafting scans the history through a `Span` with an anchor-token filter, about 6× faster on a 4k–16k-token miss, and emitting a token no longer allocates (#190).
- On recurrent hybrids the prompt cache also keeps a snapshot where a new prompt diverges from a cached one, so a third prompt sharing that prefix reuses it instead of prefilling it again (#95).
- Opt-in disk tier for the prompt cache, `--prompt-cache-disk-mb` on `serve` and `chat` (#174): on graceful shutdown, before a model switch and when `basalt chat` exits, the hottest prompt-cache branches are written with mlx-swift-lm's `savePromptCache` (dense KV and hybrid snapshots with their model state), and the first request of a resumed session or restarted server restores the longest matching prefix from disk instead of prefilling it. A file is tied to the model's weights (HF blob names, or sampled content, mtime and inode outside the HF cache), config, tokenizer and chat template, the basalt version and the cache format; any mismatch, a truncated file or a different layer layout falls back to a normal prefill. Files are atomic (temp + fsync + rename), `0600` in a `0700` directory that must be new, empty or already a prompt-cache directory, bounded by the quota with LRU eviction, a longer path of a conversation replaces the shorter files it covers, shutdown writes only what fits its deadline at an assumed 1 GB/s, expire after `--prompt-cache-disk-days`, and `basalt sessions prune` cleans them offline. Refused with `--session-log meta` or `off`.
- `basalt chat` now reuses the prompt cache between turns (#174): its requests had no cache key, so every turn prefilled the whole history again.
- Prompt lookup on dense recurrent hybrids (#162): Qwen3.5/Ornith (GatedDelta), Nemotron-H (Mamba-2) and dense LFM2 (short conv).
  - Mechanism: before each verify round the iterator keeps references to every `MambaCache` slot. No data is copied, since the models write new arrays. After a rejection it trims the attention layers to the round start, restores the slots, and replays the accepted tokens in one extra forward.
  - Backoff on hybrids: a replayed round counts one accepted draft less and pauses four times longer when it fails, and a 4-token probe comes before the 16-token draft.
  - Hybrids with expert routing (any `SwitchLinear`, e.g. LFM2.5-8B-A1B) stay on plain decoding: a k+1-token verify reads up to k+1 times the active experts, and LFM2.5 measured 0.68–0.85× on code edits.
  - Measured: code edits 2.4–3.8× on Ornith-1.5-9B, 2.9–6.2× on Nemotron-3-Nano-4B and 3.6–4.8× on Nemotron-Nano-9B-v2; prose 0.99–1.00× on Ornith, and 0.94–1.04× elsewhere outside host swings; reasoning 0.89–0.94×, like dense models.
  - Telemetry: a replay forward counts as a target-model call but not as a verified token, so verified tokens stay drafts plus one per round and per plain step.
  - Output was identical to plain decoding on code and prose. On reasoning it differed in some cells, the multi-token kernel near-tie described below.
- Opt-in Token Recycling for prompt lookup, `serve --speculative-recycling` (#38): when no n-gram matches, the model's own argmax successors, recorded after every forward and confirmed twice in a row, are drafted as a chain of up to 6 tokens and verified exactly like lookup drafts. It uses a per-request table of 5 bytes per vocabulary entry (742 KiB on Qwen3) and backs off on its own. On Qwen3-4B, reasoning-style text runs 1.02–1.15× faster than with lookup alone, but it is still below plain decoding, as lookup alone already is there. Prose accepts no recycled drafts and gains nothing, so it stays off by default. The paper's draft trees need per-token RoPE positions, which mlx-swift-lm does not expose, so recycling drafts chains only.

### Memory
- Experimental `--kv-evict F` with `--kv-zones` (on `serve` and `models check`) (#43): as tokens migrate from the recent window into the zoned cache's quantized middle, each full-attention layer drops the fraction `F` of them whose keys have the largest L2 norm, per KV head, before quantizing (arXiv:2406.11430). Fast attention stays on; `KVCacheGeometry`, `models check` and the orchestrator's room count only the kept tokens. After a 16k prompt with k8v4, Qwen3-4B holds 0.89 GB of KV at 0.25 and 0.66 GB at 0.5 instead of 1.11 GB. Quality drops: perplexity 6.71 / 7.04 against 6.56 on Qwen3-4B, 9.06 / 9.52 against 8.75 on LFM2.5-8B, unchanged on Ornith-1.5-9B; 16k passkey at five depths 4/5 at both fractions on Qwen3-4B (5/5 without), 4/5 and 3/5 on Ornith (4/5 without). Gemma 4 is excluded with the zones, and a model that prefills more than the recent window in one pass (checked at load) keeps every token and is sized so; `models check` and `serve --dry-run` print the fraction the budget assumes.

### Models
- Hadamard-rotated ternary checkpoints, `model_type: prism_hadamard_qwen35` (#204): Prism ML's Ternary Bonsai 2 (`prism-ml/Ternary-Bonsai-2-27B-mlx-2bit`, 7.4 GB active) and MTPLX packs built on it load as Qwen3.5 with their 402 rotated projections, embedding and head replaced by layers that rotate activations with a signed block Hadamard transform (stock MLX ops). After loading, the signs must be ±1, and float32 norms and convolutions run in float16. Follows mlx-swift-lm PR #630, which is not merged yet.

### Fixes
- `basalt serve --mcp` without `--rest` now persists the prompt cache and closes the session log when stdin closes or on SIGTERM/SIGINT, and shutdown runs once and is shielded from cancellation in every serve mode (#187).
- Token Recycling learns from every position of a verify forward again, and forced grammar tokens left over when `max_tokens` cuts a span are no longer dropped (#202).
- Prompt cache leases, the disk-cache `flock` and the GPU lock are single-owner (`~Copyable`) values released exactly once (#188); safetensors headers are parsed without unsafe pointers (#190).
- An already-persisted prompt-cache file costs nothing against the shutdown deadline; it is only touched.

### Performance
- Prompt lookup per request and a cost gate (#138): OpenAI chat and Responses and Anthropic messages take `speculative_lookup`, `/v1/generate` and MCP `gemma_generate` take `speculativeLookup` (a non-boolean is 400 / -32602; omitted falls back to `serve --speculative-lookup`). With nothing to verify, decoding overlaps CPU and GPU like `TokenIterator`; a draft is verified only once the model's own next token agrees with its first token, and after a rejection drafting pauses for 1, 2, 4 … 64 tokens. On Qwen3-4B free prose goes from 0.94× to 1.00× of plain decoding while code edits keep 2.9× and JSON 2.05×; greedy prose can still differ from plain decoding at a near-tie once a verify round runs.
- Prompt lookup drafts up to 16 tokens per verify round instead of 8 (#25), about 1.4–1.7× faster than 8 on code edits on Qwen3-4B and Llama-3.1-8B with prose unchanged; lookup on versus off is roughly 2.4–4.2× on code edits there. New T > 0 guard tests pin that seeded sampling, JSON constraints and presence penalties produce the same tokens with lookup on as off, and `scripts/speculative_lookup_bench.swift` runs the on/off and draft-length matrix on real models (see BENCHMARKING.md).
- CacheBlend (`--cache-blend`) spends its recompute budget on the first 32 tokens of each reused chunk before the rest, ranked by layer-1 KV deviation within each group, and `--cache-blend-ratio` now defaults to 0.3 instead of 0.5 (#137). On Qwen3-4B-4bit with `benchmarks/cacheblend`, ratio 0.3 goes from a perplexity gap of 0.085 to 0.032 against a full prefill, below the old default 0.5 (0.038) while recomputing 40% fewer tokens; on four other orders and questions the gap at 0.3 goes from 0.169 to 0.096 (old default: 0.120). Layer-progressive filtering was tried and did not beat it at the same cost.

### Memory
- `--kv-bits k8v4` with `--kv-zones` (also on `models check`, `PerformanceBenchmark`) (#24): the zoned cache's quantized middle stores keys at 8 bits and values at 4, 13 bits per K+V pair (0.41× fp16); `--kv-bits auto --kv-zones` now steps fp16 → 8-bit → k8v4 → 4-bit. `KVCacheGeometry` prices keys and values with their own head dimensions (MLA). A model the zones probe rejects (Gemma 4) runs and is sized as uniform 8-bit. Experimental `--kv-bits k8v4h` also Walsh–Hadamard-rotates the values before 4-bit quantization; opt-in only, never chosen by `auto`. Against `k8v4` its perplexity was within noise on Qwen3-4B, Ornith-1.5-9B and LFM2.5-8B (6.568 vs 6.562, 4.937 vs 4.920, 8.723 vs 8.750) and its peak after a 16k prompt about 85 MB higher on Ornith; head dimensions other than 2^k and 12·2^k stay unrotated, logged at load.
- `serve --kv-zones` (with `--kv-bits 4|8|auto`, also on `models check`) (#139): each full-attention layer keeps its first 64 tokens (attention sinks) and its last 1024 in fp16 and quantizes the tokens between them, 256 at a time, while the prompt is prefilled. There is no fp16 prefill to convert, so the prompt may use the whole quantized room and `serve --dry-run` / `models check` report one budget; sliding-window, recurrent and conv layers are untouched. Measured on Qwen3-4B-4bit: KV after a 16k prompt within 0.8% of the geometry, peak 1.03 GB at 4 bits against 3.11 GB uniform, perplexity 6.58 at 4 bits against fp16 6.56 and uniform 4-bit 8.66.

- ARC-AGI benchmark `--mode hybrid` no longer runs model-written Python with `exec()` inside the benchmark process (#78). Each attempt's code runs in a child `python3 -I -S` (grid in on stdin, result out as JSON on stdout) in an empty temp directory with an empty environment, under a `sandbox-exec` profile on macOS: deny by default, exec only of the Python binary, reads only of the Python install, `numpy` and its libraries, `/usr/lib`, `/System` and the two benchmark module files (their directory cannot be listed), writes only to the temp directory, `sysctl` reads only of the five names `os.uname()` needs, no network. Native extensions are allowlisted: of `lib-dynload` the child may read only `_posixsubprocess`, `_random`, `_struct`, `binascii`, `math`, `resource`, `select` and `zlib` (`np.random` needs the last two), and every other `*.so`/`*.dylib` under the Python install and `site-packages` is unreadable except `numpy`'s own extensions (its test modules `_multiarray_tests`, `_rational_tests`, `_umath_tests`, `_operand_flag_tests`, `_struct_ufunc_tests` and `_simd` stay denied) and the libraries a clean `import numpy` loads, whatever the benchmark parent itself has imported, so `_ctypes`, `_socket`, the `_test*` modules and any extension not on the list cannot be loaded: Seatbelt does not mediate `sysctl` `KERN_PROCARGS2`, which returns the argv and environment of any same-user process (the benchmark parent included), so the child must not reach raw syscalls; a CPython or `numpy` memory-corruption exploit remains a residual path. ### Concurrency
- Behaviour change: generations are bounded (#74). `--max-concurrent` (default 1) decode at once, `--max-queue` (default 8) wait in arrival order, the rest get 503 with `Retry-After: 1` (`BasaltError.serverBusy`); a stream holds its slot until its consumer finishes or disconnects, and a client that leaves while queued frees its place. Before, every request decoded concurrently with its own KV cache. Model switches are single-flight (concurrent loads of the same model share one, a different model meanwhile is 503 `modelSwitching`) and wait for running generations, with new requests queued behind them, instead of unloading under live streams. On SIGTERM/SIGINT the server stops admitting, gives generations 5 s, then cancels them so the process exits.

### Memory
- `models check` and `serve --dry-run` judge the fit against Metal's recommended working set (what MLX can use; 3/4 of RAM when Metal reports none) instead of momentary free + inactive memory × 1.25, which refused models that `serve` runs (LFM2.5-24B-A2B 4-bit on a 24 GB Mac with 9–11 GB free at that moment). Fit levels are 60 / 90 / 100 % of that budget; when the model fits but needs more than is free right now, a note says macOS will compress or swap other apps. The context budget matches `serve`'s cap: half of the working set left after the weights (the other half is the default prompt-cache budget), and the output shows the budget.
- Behaviour change: `max_tokens` is capped at min(requested, `--max-tokens`, KV room − prompt tokens) (#85). `--max-tokens` used to be a floor the memory budget could only raise, so a 40k-token prompt with `max_tokens` 65536 on Qwen3-4B (≈15 GiB of KV) was accepted on a 24 GB Mac and swapped or failed mid-generation. The KV room is computed once at load: Metal's recommended working set minus the loaded weights and the prompt-cache budget (it used to read free memory after the load and subtract the weights again). The prompt is counted with the model's tokenizer instead of UTF-8 bytes / 4. A prompt that does not fit at all is 413 before generation. The orchestrator's default ceiling is 65536, the `serve` default, so `basalt harness` is no longer held to 4096. The cloud fallback's memory reason uses the same KV room.

Out-of-range values are 400 before a stream opens (#105).
- Behaviour change: a request that does not set `temperature`, `top_p` or `top_k` samples with the model's `generation_config.json` (Qwen3.8: 1.0 / 0.95 / 20), falling back to 0.7 / 0.9 / off; `--top-k` and `--repetition-penalty` still beat the model file (#105).
- LFM2.5 MoE (`lfm2_moe`: LFM2.5-24B-A2B, LFM2.5-8B-A1B) get a Liquid profile: `thinking_budget` now applies to them with the same transition as Qwen (it was silently ignored, so these always-thinking models could not be held to a reasoning budget). `reasoning_effort: none` cannot switch their thinking off; neither the model nor its template has a switch (#113).
- `repetition_penalty` in `generation_config.json` is honoured (LFM2.5-24B-A2B: 1.05); the request and `--repetition-penalty` still win (#113).
- Usage reports reasoning tokens: `completion_tokens_details.reasoning_tokens` on chat (streamed when `stream_options.include_usage` is set), `output_tokens_details.reasoning_tokens` on Responses; always present, `0` when the model did not reason; a forced thinking-budget transition counts as reasoning (#105).
- ARC-AGI benchmark: the test grid is labelled `TEST_IN` instead of `IN`, the hybrid instructions are neutral (find the rule mapping every example IN to its OUT; DSL optional), the last 8 code blocks (from the last written) run newest first, each in its own sandbox child, on the training inputs and the test input; the parent compares the training outputs (the child never sees them), and the first block that reproduces every training OUT gives the answer; otherwise the attempt fails as `train_mismatch` with the best block's `train_pairs_passed`; a grid larger than 30×30 counts as no answer; a reply with code never falls back to a JSON grid in the text (`exec_failed`); `--exec-timeout` is a deadline on every block × grid call, and each block's child gets `--exec-timeout` × grids + 3 s for startup; a block that overruns it, hits the memory or disk limit, or prints an unparsable or oversized result line fails alone and the next block is tried; `--answer-tokens` (default 4000) sets `max_tokens` to `--thinking-budget` plus it unless `--max-tokens` is larger; and `--reasoning-effort`, `--thinking-budget`, `--top-k`, `--presence-penalty` are passed to the server; `--temperature` now defaults to the model's own (#105).

### Sampling
- Per-request `min_p` (`minP` on `/api/v1/generate` and MCP) overrides `--min-p` and the model profile default; `0` turns Min-P off for that request. Validated to 0–1 (#40).
- `dynamic_temperature` (`dynamicTemperature`): entropy-based dynamic temperature (EDT, arXiv:2403.14541), `T = T0·N^(θ/H) + γ·R` with N = 0.8, θ = 1.5, γ = 0.5, clamped to 0.05–2 (a request colder than 0.05 keeps its own temperature as the floor). Confident tokens sample near-greedy; a forming repetition loop raises the temperature. With EDT on, `top_p`/`min_p` still cut the original distribution, not the heated one. Off by default; no effect at temperature 0 (#40).
- `RepetitionGuard` exposes a continuous repetition score in [0, 1] alongside its stop decision (#40).

### Prompt cache
- Prefix KV-cache reuse across conversations: a radix tree keeps the KV cache of recent prompts, one node per shared token run. A request takes the longest stored prefix and prefills only the rest, so the next turn of a conversation, and a second conversation with the same system prompt and tools (a Claude Code subagent, another Codex thread), reuse what is already computed instead of prefilling it again; concurrent requests on one prefix both reuse it. All clients share one tree; `prompt_cache_key`, `metadata.user_id` and `x-session-id` are not needed and are ignored; service requests are never cached. Sliding-window layers such as Gemma 3/4 and `--kv-bits` prefill in full (#56, #32).
- Prefix reuse for hybrid attention/SSM models (Qwen3.5/3.6, Ornith-1.5): the prompt is prefilled in two phases and the recurrent state is snapshotted at the end of the request text, before the chat template's closing tokens; the next turn that extends the text restores the snapshot and prefills only the tail, with `cached_tokens` reporting the restored length. Snapshots count against `--prompt-cache-mb`. Ornith-1.5-9B, 12.6k-token agent prompt: second turn ≈1 s instead of ≈36 s. A reused turn can differ from an uncached one after its first tokens (bf16 drift from a different prefill chunking: restored state ≡ two-phase prefill from scratch bitwise, vs one-phase max |Δlogit| 1.56 with the same top 5). Under the byte budget a snapshot branch is evicted whole, and a growing conversation keeps only its two newest snapshots (the newest to continue from, its parent so an edited or regenerated last message still restores); older ones on a single-child chain are dropped and the chain is merged. A conversation sharing only the system prompt with another still prefills in full (#79).
- `--prompt-cache-mb` (default: half of what Metal's recommended GPU working set leaves after the weights; `0` disables) caps the memory of the tree, counted on the stored prompt tokens only, each shared prefix once. Over budget the least recently used branch is cut from its end, so an idle conversation keeps its head (system prompt and tools) longest; a branch in use by a running request is never evicted; a prompt larger than the budget keeps the longest head that fits (#56, #32).
- The tree also holds at most 4096 branches (leaves) in all; beyond that the least recently used free branch is dropped, a branch in use never (#32).
- Usage reports the tokens actually reused: `prompt_tokens_details.cached_tokens`, `input_tokens_details.cached_tokens`, `cache_read_input_tokens` (see Upgrading for Anthropic `input_tokens`). `cached_tokens` reveals how much of a prompt matched an earlier prompt from any client; see the README before sharing a server (#56, #32).
- `--cache-blend` (opt-in, approximate): CacheBlend non-prefix KV reuse (arXiv:2405.16444). Prompt chunks (split after blank lines) keep their pre-RoPE KV and are reused at any position; the first layer is recomputed for all tokens and only the `--cache-blend-ratio` (default 0.5) most deviating reused tokens on later layers. Six reordered files of 550–900 tokens on Qwen3-4B-4bit, teacher-forced top-1 agreement with a full prefill on 200 positions / time to first token: full prefill 0.995 / 10.9 s, ratio 0.5 0.950 / 6.7 s, ratio 0.15 0.930 / 3.7 s, ratio 0 0.925 / 1.1 s — the paper's 0.15 barely beats no recomputation on this sample, hence 0.5. Chunks end at a blank line in one token or across two newline tokens (SentencePiece); chunks under 16 tokens are recomputed; a prompt is blended only when (1 − ratio) × reused share ≥ 0.2 (the blended forward costs ~1.2× native per recomputed token) and the cache stays within 16 384 tokens, otherwise it takes the native chunked prefill and stores its chunks from that cache; ratio 1 is always native. Llama and Qwen3 dense models only; the prompt-cache budget is split in half with the tree; `cached_tokens` counts only exact prefix-tree tokens, blended ones are logged (#36).
- Removed the unused string-based `MultiSlotConversationCache`, `PromptContextBuilder.extractToolPrefix` / `compactWithToolPrefixProtection` and the orchestrator's working-session tracker; the engine's token-level prefix tree replaces them (#56, #32).

### Fixed
- KV-cache memory is estimated from the model's geometry instead of 2 bytes per token (token budget) and 8 bytes per token (memory check): `2 · layers · kv_heads · head_dim · bytes` per token from `config.json` (`text_config` for VLM wrappers), only full-attention layers growing for hybrid models (Ornith-1.5/Qwen3.5: 8 of 32) plus their fixed SSM state, sliding-window layers capped at the window, Gemma 4 full-attention layers with `global_head_dim` (and `num_global_key_value_heads` when `attention_k_eq_v`) and without the `num_kv_shared_layers` that hold no cache, MLA (DeepSeek V2/V3) as the per-head K and V that MLX caches, Jamba and NemotronH attention layers from `attn_layer_period` / `hybrid_override_pattern`, `--kv-bits` as `bits + 0.5` bits per element (`bits + 1` when `head_dim` is not a multiple of 64 and MLX quantizes in groups of 32); `--kv-bits` does not apply to sliding-window layers. The memory-derived token budget is now computed correctly and subtracts the prompt (Qwen3-4B on 16 GB free: 77.5k instead of 128k); cap = max(--max-tokens, memory budget); the budget can only raise it above --max-tokens (see #85); `serve --dry-run` (which takes `--kv-bits`), `models check` and `fit` (its quantization grid and decode-speed estimate; the RAM column and fit level still count weights only) include the KV cache for every model: Qwen3-4B at 32k tokens needs 4.5 GiB of KV, Ornith-1.5-9B 1.05 GiB. Without a cached config the parameter-count estimate of `fit` is the fallback (#75).
- Non-streaming `/v1/chat/completions` and `/v1/responses` answered 500 to an invalid request (e.g. `temperature` or `min_p` out of range); they now return the error's own status, 400 for a bad field.

## 0.3.0 — 2026-10-19

### Upgrading from 0.2.0
- `basalt serve --host` off loopback now refuses to start without a key: set `BASALT_API_KEY`, pass `--api-key`, or `--auto-generate-key`. Clients send it as `Authorization: Bearer` or `x-api-key`.
- Off loopback the server answers 429 beyond 120 requests per minute; raise it with `--rate-limit N`, turn it off with `--rate-limit 0`.
- Building from source (Homebrew included) needs Xcode 26.4+ (Swift 6.3): mlx-swift now declares swift-tools-version 6.3.
- The config stays in `~/.gem/`. The command is still `basalt`.
- Earlier versions left the last request body in `/tmp/basalt_anthropic_request.json` and `/tmp/basalt_openai_request.json`: delete them.

### Security
- An API key is mandatory when serving off loopback (`BASALT_API_KEY`, `--api-key` or `--auto-generate-key`); the key check runs on every route except health and docs. `~/.gem/config.json` is written owner-only and merged, never overwritten (#28, #48).
- Token-bucket rate limit, 429 with `Retry-After`: on by default off loopback (120 req/min), `--rate-limit N` or `rate_limit` in the config, `0` disables (#19, #57).
- `/v1/messages` and `/v1/chat/completions` no longer write every request body (prompts, code, anything pasted) to world-readable files in `/tmp` (`basalt_anthropic_request.json`, `basalt_openai_request.json`). Delete those files if they exist.

### Coding agents
- OpenAI Responses API (`/v1/responses`) with the event sequence Codex expects, `reasoning.effort`, and tool calling end to end: tool definitions reach the model, tool calls stream back to the client (#27, #52).

- Fixed: with tools in the request, the answer was replaced by its first `{…}` fragment, which mangled every Claude Code reply containing code (#53).
