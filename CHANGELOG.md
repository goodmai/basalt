# Changelog

## Unreleased

### Performance
- Opt-in disk tier for the prompt cache, `--prompt-cache-disk-mb` on `serve` and `chat` (#174): on graceful shutdown, before a model switch and when `basalt chat` exits, the hottest prompt-cache branches are written with mlx-swift-lm's `savePromptCache` (dense KV and hybrid snapshots with their model state), and the first request of a resumed session or restarted server restores the longest matching prefix from disk instead of prefilling it. A file is tied to the model's weights (HF blob names, or sampled content, mtime and inode outside the HF cache), config, tokenizer and chat template, the basalt version and the cache format; any mismatch, a truncated file or a different layer layout falls back to a normal prefill. Files are atomic (temp + fsync + rename), `0600` in a `0700` directory that must be new, empty or already a prompt-cache directory, bounded by the quota with LRU eviction, a longer path of a conversation replaces the shorter files it covers, shutdown writes only what fits its deadline at an assumed 1 GB/s, expire after `--prompt-cache-disk-days`, and `basalt sessions prune` cleans them offline. Refused with `--session-log meta` or `off`.
- `basalt chat` now reuses the prompt cache between turns (#174): its requests had no cache key, so every turn prefilled the whole history again.
- Prompt lookup on dense recurrent hybrids (#162): Qwen3.5/Ornith (GatedDelta), Nemotron-H (Mamba-2) and dense LFM2 (short conv).
  - Mechanism: before each verify round the iterator keeps references to every `MambaCache` slot. No data is copied, since the models write new arrays. After a rejection it trims the attention layers to the round start, restores the slots, and replays the accepted tokens in one extra forward.
  - Backoff on hybrids: a replayed round counts one accepted draft less and pauses four times longer when it fails, and a 4-token probe comes before the 16-token draft.
  - Hybrids with expert routing (any `SwitchLinear`, e.g. LFM2.5-8B-A1B) stay on plain decoding: a k+1-token verify reads up to k+1 times the active experts, and LFM2.5 measured 0.68–0.85× on code edits.
  - Measured: code edits 2.4–3.8× on Ornith-1.5-9B, 2.9–6.2× on Nemotron-3-Nano-4B and 3.6–4.8× on Nemotron-Nano-9B-v2; prose 0.99–1.00× on Ornith, and 0.94–1.04× elsewhere outside host swings; reasoning 0.89–0.94×, like dense models.
  - Telemetry: a replay forward counts as a target-model call but not as a verified token, so verified tokens stay drafts plus one per round and per plain step.
  - Output was identical to plain decoding on code and prose. On reasoning it differed in some cells, the multi-token kernel near-tie described below.
- Opt-in Token Recycling for prompt lookup, `serve --speculative-recycling` (#38): when no n-gram matches, the model's own argmax successors, recorded after every forward and confirmed twice in a row, are drafted as a chain of up to 6 tokens and verified exactly like lookup drafts. It uses a per-request table of 5 bytes per vocabulary entry (742 KiB on Qwen3) and backs off on its own. On Qwen3-4B, reasoning-style text runs 1.02–1.15× faster than with lookup alone, but it is still below plain decoding, as lookup alone already is there. Prose accepts no recycled drafts and gains nothing, so it stays off by default. The paper's draft trees need per-token RoPE positions, which mlx-swift-lm does not expose, so recycling drafts chains only.

### Memory
- Experimental `--kv-evict F` with `--kv-zones` (on `serve` and `models check`) (#43): as tokens migrate from the recent window into the zoned cache's quantized middle, each full-attention layer drops the fraction `F` of them whose keys have the largest L2 norm, per KV head, before quantizing (arXiv:2406.11430). Fast attention stays on; `KVCacheGeometry`, `models check` and the orchestrator's room count only the kept tokens. After a 16k prompt with k8v4, Qwen3-4B holds 0.89 GB of KV at 0.25 and 0.66 GB at 0.5 instead of 1.11 GB. Quality drops: perplexity 6.71 / 7.04 against 6.56 on Qwen3-4B, 9.06 / 9.52 against 8.75 on LFM2.5-8B, unchanged on Ornith-1.5-9B; 16k passkey at five depths 4/5 at both fractions on Qwen3-4B (5/5 without), 4/5 and 3/5 on Ornith (4/5 without). Gemma 4 is excluded with the zones, and a model that prefills more than the recent window in one pass (checked at load) keeps every token and is sized so; `models check` and `serve --dry-run` print the fraction the budget assumes.

### Chat templates and API
- A conversation that ends with an assistant message is continued instead of answered in a new turn (#98), on `/v1/messages`, `/v1/chat/completions` and `/v1/responses`: the earlier turns get the thinking-off generation prompt, the assistant text follows it unclosed (the shape of transformers' `continue_final_message`, checked on six cached templates), and the response holds only the continuation, as on the Anthropic API. The prefill is committed into a `response_format` or forced-tool grammar, so `{` plus a schema is one document; a prefill that opens a thinking block keeps thinking on (its leading `<think>` is dropped where the template already opened one). Control tokens in a prefill are neutralized, so it cannot forge a turn, and a prefilled request never goes to `--cloud-fallback`. Checked locally on Qwen3-4B, Ornith-1.5-9B and Gemma 4 12B: `{"name":` continues into valid JSON and `Sure, here` continues the sentence.

## 0.7.0 — 2026-10-29

### Upgrading from 0.6.0
- `--cache-blend-ratio` now defaults to 0.3 instead of 0.5 (#137). Pass `--cache-blend-ratio 0.5` to keep the old recompute budget.
- `--kv-bits` accepts only the widths MLX quantizes (2–6 and 8) plus `k8v4`/`k8v4h`; 7 or 16 used to pass validation and crash MLX at the first quantized layer (#24).
- `--kv-zones` (#139) and `--kv-bits k8v4` (#24) are new and opt-in; without them memory behaves as in 0.6.0.
- Prompt-lookup speculative decoding drafts up to 16 tokens instead of 8 and pauses after rejected drafts (#138, #25); it is still opt-in, now also per request with `speculative_lookup` / `speculativeLookup`.

### Performance
- Prompt lookup per request and a cost gate (#138): OpenAI chat and Responses and Anthropic messages take `speculative_lookup`, `/v1/generate` and MCP `gemma_generate` take `speculativeLookup` (a non-boolean is 400 / -32602; omitted falls back to `serve --speculative-lookup`). With nothing to verify, decoding overlaps CPU and GPU like `TokenIterator`; a draft is verified only once the model's own next token agrees with its first token, and after a rejection drafting pauses for 1, 2, 4 … 64 tokens. On Qwen3-4B free prose goes from 0.94× to 1.00× of plain decoding while code edits keep 2.9× and JSON 2.05×; greedy prose can still differ from plain decoding at a near-tie once a verify round runs.
- Prompt lookup drafts up to 16 tokens per verify round instead of 8 (#25), about 1.4–1.7× faster than 8 on code edits on Qwen3-4B and Llama-3.1-8B with prose unchanged; lookup on versus off is roughly 2.4–4.2× on code edits there. New T > 0 guard tests pin that seeded sampling, JSON constraints and presence penalties produce the same tokens with lookup on as off, and `scripts/speculative_lookup_bench.swift` runs the on/off and draft-length matrix on real models (see BENCHMARKING.md).
- CacheBlend (`--cache-blend`) spends its recompute budget on the first 32 tokens of each reused chunk before the rest, ranked by layer-1 KV deviation within each group, and `--cache-blend-ratio` now defaults to 0.3 instead of 0.5 (#137). On Qwen3-4B-4bit with `benchmarks/cacheblend`, ratio 0.3 goes from a perplexity gap of 0.085 to 0.032 against a full prefill, below the old default 0.5 (0.038) while recomputing 40% fewer tokens; on four other orders and questions the gap at 0.3 goes from 0.169 to 0.096 (old default: 0.120). Layer-progressive filtering was tried and did not beat it at the same cost.

### Memory
- `--kv-bits k8v4` with `--kv-zones` (also on `models check`, `PerformanceBenchmark`) (#24): the zoned cache's quantized middle stores keys at 8 bits and values at 4, 13 bits per K+V pair (0.41× fp16); `--kv-bits auto --kv-zones` now steps fp16 → 8-bit → k8v4 → 4-bit. `KVCacheGeometry` prices keys and values with their own head dimensions (MLA). A model the zones probe rejects (Gemma 4) runs and is sized as uniform 8-bit. Experimental `--kv-bits k8v4h` also Walsh–Hadamard-rotates the values before 4-bit quantization; opt-in only, never chosen by `auto`. Against `k8v4` its perplexity was within noise on Qwen3-4B, Ornith-1.5-9B and LFM2.5-8B (6.568 vs 6.562, 4.937 vs 4.920, 8.723 vs 8.750) and its peak after a 16k prompt about 85 MB higher on Ornith; head dimensions other than 2^k and 12·2^k stay unrotated, logged at load.
- `serve --kv-zones` (with `--kv-bits 4|8|auto`, also on `models check`) (#139): each full-attention layer keeps its first 64 tokens (attention sinks) and its last 1024 in fp16 and quantizes the tokens between them, 256 at a time, while the prompt is prefilled. There is no fp16 prefill to convert, so the prompt may use the whole quantized room and `serve --dry-run` / `models check` report one budget; sliding-window, recurrent and conv layers are untouched. Measured on Qwen3-4B-4bit: KV after a 16k prompt within 0.8% of the geometry, peak 1.03 GB at 4 bits against 3.11 GB uniform, perplexity 6.58 at 4 bits against fp16 6.56 and uniform 4-bit 8.66.

## 0.6.0 — 2026-10-27

### Upgrading from 0.5.0
- Queued requests are admitted by priority (#140): `basalt chat` first, then service requests and the harness, then the API, then benchmarks. When the queue is full, a higher-priority request turns away the lowest-priority waiter with 503 `Retry-After: 1` instead of being refused itself.
- A fixed `--kv-bits 4|8` now refuses with 413 a prompt whose fp16 prefill plus quantization copy does not fit, instead of admitting it and running out of memory (#139). `--kv-bits auto` is new and stays fp16 until a request needs more room.
- `basalt chat` keeps a multi-turn history and logs its own session; `basalt chat --resume <id|latest>` continues one (#106).
- Chat templates now go through basalt's own Jinja2 whitespace handling, so prompts can differ slightly from 0.5.0 where swift-jinja diverged from transformers (Gemma 4 tool prompts, `{#- … #}` comments, CRLF templates) (#104).
- `/v1/chat/completions` adds `reasoning_content` next to `reasoning` (#104).

### Performance
- Prompt-lookup speculative decoding, opt-in with `serve --speculative-lookup` (#138): up to 8 tokens drafted from an n-gram match against the prompt and the output, verified in one forward pass; sampling stays exact with constraints and penalties. About 2.1× on code edits and 1.7× on JSON echoes, slower on free prose (0.89×), so no profile enables it; attention-only models without `--kv-bits`.
- Constrained decoding (#141): building the JSON mask processor no longer materializes the vocabulary index on the CPU (~10 ms per constrained request on a 152k vocabulary, now ~2 µs), and the per-step mask remap is gone. The grammar pool evicts the least recently used schema when a 17th arrives instead of dropping all 16, so agent loops cycling through many tool schemas stop recompiling them (7 ms on Qwen3, 13.5 ms on Gemma 4 per miss).

### Memory
- `--kv-bits auto` (#139): the KV cache stays fp16, with prompt-cache reuse, while a request's prompt plus its `max_tokens` fits the KV room; otherwise that request alone runs at 8, else 4 bits. A request without `max_tokens` is capped as before and never quantized. `serve --dry-run` and `models check --kv-bits` print the longest prompt next to the context budget.
- Behaviour change: with a fixed `--kv-bits 4|8` the room now accounts for how mlx-swift-lm quantizes — the prompt is prefilled in fp16 and converted afterwards, briefly holding both copies — so a prompt that fits 4-bit room but not that fp16 peak is refused with 413 instead of admitted and run out of memory. Quantization buys generation room, not a longer prompt; measured on Qwen3-4B-4bit the KV is 46.9% smaller at 8 bits and 71.9% at 4 bits, peak memory on a 16k prompt is not lower.

### Concurrency
- Priority admission (#140): queued generations are admitted interactive (`basalt chat`) → tool validation (service requests, harness) → standard (API) → background (benchmark), first come first served within a level; when the queue is full a higher-priority request turns away the lowest-priority waiter with 503. A stream's prefill is now cancellable by a server shutdown (the cancel hook is registered before the prefill starts), and CacheBlend's own prefill loop stops on cancellation; the model prefill was already chunked and cancellation-checked per chunk by mlx-swift-lm, so a client that disconnects or a drain stops a 16k-token prefill within about one chunk.

### Session log
- Sessions (#106): `X-Basalt-Session` names the session (`x-session-id` as an alias); without an id a request that extends an earlier conversation joins its session, anything else gets a new `s-…` id. A known id appends to its existing file after a restart with a `session_resume` line and continues the `parent` chain (the last 8 conversations are reloaded from the file); `--session-idle-minutes` (default 30) writes `session_suspend` and closes an idle file, the next request resumes it with `gap_s`. Resume across restarts needs an explicit id.
- `basalt sessions list | show <id|latest> | stats <id|latest>` read the log without loading a model; `show` rebuilds the latest conversation from the `parent` chain (metrics only for `meta` sessions).
- Behaviour change: `basalt chat` keeps a multi-turn history (it sent each line on its own before) in a session of its own (`--session-log full|meta|off`), prints `Resume with: basalt chat --resume <id>` on exit, and `basalt chat --resume <id|latest>` continues a logged chat; a `meta` session has no content and is refused with a non-zero exit. `/clear` clears the history.

### Chat templates and API
- Chat templates render as Python Jinja2 does under HF transformers (#104): basalt applies `{%- -%}` / `{{- -}}` / `{#- -#}` whitespace control, `{%+` / `+%}`, `lstrip_blocks` and `trim_blocks` itself before swift-jinja sees the template, aware of string literals and `{% raw %}` blocks (which swift-jinja does not parse), and normalizes CRLF. Gemma 4 tool declarations lose the stray spaces in `parameters:{ properties:{ …`; the ten cached model templates checked against `transformers` produce the same tokens for the test conversations.
- `/v1/chat/completions` returns reasoning as both `reasoning` and `reasoning_content` (`message` and stream `delta`), for vLLM, DeepSeek, llama.cpp and LM Studio clients (#104). The README notes that Anthropic `thinking` blocks carry an empty `signature`.

## 0.5.0 — 2026-10-27

### Upgrading from 0.4.0
- `basalt serve` now keeps a local session log by default: `~/.basalt/sessions/<date>/<session>.jsonl` in `full` mode, which stores the prompts and replies on this machine, with private keys and API tokens redacted. Use `--session-log meta` for metrics and hashes only, or `--session-log off` to write nothing. Files are deleted after 14 days or beyond 1 GB at start (#106).

### Session log
- `basalt serve` writes a local JSONL session log (#106): `request` before every engine call and `response` after it (status `ok`/`error`/`timeout`/`cancelled`, tokens, timing with queue wait, memory, finish reason, output size and SHA-256), `error` for requests rejected before generation (size only), `model_switch`, `dropped`. One record structure for `/v1/messages`, `/v1/chat/completions`, `/v1/responses`, `/api/v1/generate`, MCP and `basalt chat`; only `source` and `endpoint` differ. `--session-log full` (default) also stores the conversation and the reply, `meta` only metrics and hashes, `off` nothing; files are `0700`/`0600` under `~/.basalt/sessions/`, retention 14 days / 1 GB. Headers are never recorded. The writer appends with one `write(2)` per record, never blocks generation (bounded buffer, counted drops) and disables itself with one warning on an I/O error. `docs/PRIVACY_POLICY.md` describes it, and now also says that the opt-in cloud fallback sends requests to the configured endpoint.
- In `full` mode the log redacts private-key blocks and API tokens (`sk-`/`sk-ant-`, `ghp_`…/`github_pat_`, `AKIA`/`ASIA`, `xox[bpas]-`, `Bearer …`) to `[REDACTED:*]` in prompts, replies, reasoning and tool arguments; on by default, `--session-log-redact off` disables it; best effort, linear in the input (a 1 MB adversarial prompt in well under 200 ms). A request whose `messages` extend one of the last 8 of its session stores only the new tail with `parent` and `prefix_count`, so a long agent conversation no longer grows the file quadratically (#106).

## 0.4.0 — 2026-10-27

### Upgrading from 0.3.0
- One generation decodes at a time by default and up to 8 requests wait in line; beyond that the server answers 503 with `Retry-After` — raise `--max-concurrent` / `--max-queue` for parallel agents (#74, #121).
- `--max-tokens` is now a ceiling: a request is capped at min(its `max_tokens`, `--max-tokens`, what the KV cache can hold after the prompt), and a prompt that cannot fit at all is 413 (#85).
- `repetition_penalty` from a model's `generation_config.json` now applies when neither the request nor `--repetition-penalty` sets one (#113).
- A repetition loop now ends the answer early with finish reason `length` / `max_tokens` (#87).
- Cloud fallback, cost routing and virtual keys are off unless configured (`--cloud-fallback`, `cloud_fallback`, `virtual_keys` in `~/.gem/config.json`) (#22, #34).
- Building from source needs nothing new; `ServiceLifecycle` is now a direct dependency (already resolved before).
- Sampling defaults changed: a request without `temperature`, `top_p` or `top_k` now samples with the model's `generation_config.json` (Qwen3.8: 1.0 / 0.95 / 20) instead of 0.7 / 0.9 / off; send them explicitly to keep the old behaviour. `/v1/messages` no longer fills in 0.7 / 0.9 either (#105).
- `curl -d '…'` without `-H "Content-Type: application/json"` now gets 415; a browser app on any other origin, a UI on another local port included, needs `--allow-origin` (#72).
- `POST /v1/models/load` accepts only a Hugging Face repo id `org/name` (or its `claude-local/org--name` form), characters `A-Z a-z 0-9 - _ .`; anything else, local paths included, is 400 (#72).
- Anthropic `/v1/messages` usage: `input_tokens` is now only the uncached remainder, as in Anthropic's API; the reused part is in `cache_read_input_tokens`. A client that took `input_tokens` as the whole prompt size must add the two (#56).

### Security
- Dependencies: Hummingbird 2.27.1 → 2.28.0 (the cap below 2.28 is lifted: swift-distributed-tracing 1.7.2 no longer collides with swift-service-context 1.5.1), swift-jinja 2.4.2 → 2.5.2 (floor raised to 2.5.1), swift-service-lifecycle 2.12 → 2.13 and 16 transitive minor/patch bumps (swift-nio 2.104, swift-http-types 1.8, swift-collections 1.7.5, swift-log 1.16.2, swift-crypto 4.5.2, …). swift-jinja's `tojson` now matches Python's `json.dumps` (`{"city": "Paris"}`), so rendered tool-call arguments in chat templates read as they do under HF transformers; its own `{#- -#}` whitespace control replaces basalt's comment-stripping workaround, which is removed.
- Chat-template control tokens inside message text no longer forge turns (#99). A user, tool or assistant-history message containing `<|im_end|>\n<|im_start|>system …` (Qwen, LFM), `<turn|><|turn>system` (Gemma 4) or any other markup-shaped added token of the model's tokenizer (read from `tokenizer.json` / `tokenizer_config.json` at load) became real role-boundary tokens. The engine now inserts U+2060 WORD JOINER after the first character of each such string in message content and tool-call arguments before the template renders, so it tokenizes as plain text; the template's own markup keeps its special tokens. A bare prompt wrapped into a user turn is treated the same; an explicitly raw `<|turn|>` / `<|channel|>` prompt is unchanged by design.
- The MCP tool `playwright_screenshot` is removed (#67). It interpolated the `url` argument into a generated Python script run with `/usr/bin/python3`, so a crafted url executed code as the server user; it had never run (the script did not parse), so no client depended on it.
- REST on loopback no longer trusts browsers (#72). DNS rebinding (an attacker's domain re-resolved to 127.0.0.1, the class of Ollama CVE-2024-28224) is stopped by a `Host` check: on loopback only `localhost`, `127.0.0.1`, `[::1]` (any port), else 403; a specific non-loopback bind also accepts its own address, a `0.0.0.0`/`::` bind accepts any `Host` because the API key is mandatory there. A request carrying an `Origin` other than the server's own loopback origin (`localhost`, `127.0.0.1`, `[::1]` on the bound port; no port means 80/443) gets 403 unless allow-listed, so a page on another local port (a dev server, Jupyter) cannot drive the API either; allow-list it with `--allow-origin` (repeatable) or `allowed_origins` in `~/.gem/config.json`; requests without `Origin` (curl, SDKs, Claude Code, Codex) are unaffected. Every `POST` needs `Content-Type: application/json`, else 415, which removes the no-preflight CORS "simple request". These checks run before the API key and the rate limit.
- `POST /v1/models/load` accepts only Hugging Face repo ids (`org/name`); local paths, `..` and `claude-local/..--x` are 400. In the `model` field of `/v1/messages`, `/v1/chat/completions` or `/v1/responses` a path form (starting with `/`, `.` or `~`, or containing `..`, after trimming whitespace) is 400 too; any other value that is not a repo id (`basalt`, `meta-llama/llama-3.1-8b-instruct:free`, `org/name@rev`) is an alias served by the loaded model, with no switch. Local paths stay available to `basalt serve --model-path` and MCP `switch_model` (#72).
- A model directory without a readable `config.json` is refused before the serving model is unloaded, so a bad load no longer leaves the server without a model (#72).
- REST error bodies no longer contain filesystem paths or echo the requested model id of a failed load (the endpoint was a file-existence oracle); the full error is in the server log (#72).
- ARC-AGI benchmark `--mode hybrid` no longer runs model-written Python with `exec()` inside the benchmark process (#78). Each attempt's code runs in a child `python3 -I -S` (grid in on stdin, result out as JSON on stdout) in an empty temp directory with an empty environment, under a `sandbox-exec` profile on macOS: deny by default, exec only of the Python binary, reads only of the Python install, `numpy` and its libraries, `/usr/lib`, `/System` and the two benchmark module files (their directory cannot be listed), writes only to the temp directory, `sysctl` reads only of the five names `os.uname()` needs, no network. Native extensions are allowlisted: of `lib-dynload` the child may read only `_posixsubprocess`, `_random`, `_struct`, `binascii`, `math`, `resource`, `select` and `zlib` (`np.random` needs the last two), and every other `*.so`/`*.dylib` under the Python install and `site-packages` is unreadable except `numpy`'s own extensions (its test modules `_multiarray_tests`, `_rational_tests`, `_umath_tests`, `_operand_flag_tests`, `_struct_ufunc_tests` and `_simd` stay denied) and the libraries a clean `import numpy` loads, whatever the benchmark parent itself has imported, so `_ctypes`, `_socket`, the `_test*` modules and any extension not on the list cannot be loaded: Seatbelt does not mediate `sysctl` `KERN_PROCARGS2`, which returns the argv and environment of any same-user process (the benchmark parent included), so the child must not reach raw syscalls; a CPython or `numpy` memory-corruption exploit remains a residual path. A wall-clock timeout (`--exec-timeout`, 10 s), `RLIMIT_CPU`, `RLIMIT_NPROC=0`, `RLIMIT_NOFILE`, `RLIMIT_FSIZE` and a 1 GiB memory watchdog stop runaway code (the parent samples the child's `ri_phys_footprint` via `proc_pid_rusage` every 10 ms; a soft cap: a 4 GiB `memset` on a fully loaded machine peaked at 1.08-1.23 GiB); a 64 MiB cap on the temp directory (every entry counts as at least 4 KiB, so empty files count too) stops code that writes many files; the attempt is recorded as `exec_timeout` / `exec_memory_limit` / `exec_disk_limit` and the run continues. macOS refuses `RLIMIT_AS`/`RLIMIT_DATA`, hence the watchdog. Without `sandbox-exec` (Linux) the default mode is now `direct`, and an explicit `--mode hybrid` warns that the code can still read files and reach the network. The DSL classes moved to `benchmarks/arc-agi/arc_helpers.py`; `--engine-url` points the benchmark at a server on any port. The default results file name now ends with the mode (`arc_benchmark_results_<engine>_<split>_<mode>.json`), so a hybrid and a direct run no longer overwrite or `--resume` each other.

### Concurrency
- Behaviour change: generations are bounded (#74). `--max-concurrent` (default 1) decode at once, `--max-queue` (default 8) wait in arrival order, the rest get 503 with `Retry-After: 1` (`BasaltError.serverBusy`); a stream holds its slot until its consumer finishes or disconnects, and a client that leaves while queued frees its place. Before, every request decoded concurrently with its own KV cache. Model switches are single-flight (concurrent loads of the same model share one, a different model meanwhile is 503 `modelSwitching`) and wait for running generations, with new requests queued behind them, instead of unloading under live streams. On SIGTERM/SIGINT the server stops admitting, gives generations 5 s, then cancels them so the process exits.

### Memory
- `models check` and `serve --dry-run` judge the fit against Metal's recommended working set (what MLX can use; 3/4 of RAM when Metal reports none) instead of momentary free + inactive memory × 1.25, which refused models that `serve` runs (LFM2.5-24B-A2B 4-bit on a 24 GB Mac with 9–11 GB free at that moment). Fit levels are 60 / 90 / 100 % of that budget; when the model fits but needs more than is free right now, a note says macOS will compress or swap other apps. The context budget matches `serve`'s cap: half of the working set left after the weights (the other half is the default prompt-cache budget), and the output shows the budget.
- Behaviour change: `max_tokens` is capped at min(requested, `--max-tokens`, KV room − prompt tokens) (#85). `--max-tokens` used to be a floor the memory budget could only raise, so a 40k-token prompt with `max_tokens` 65536 on Qwen3-4B (≈15 GiB of KV) was accepted on a 24 GB Mac and swapped or failed mid-generation. The KV room is computed once at load: Metal's recommended working set minus the loaded weights and the prompt-cache budget (it used to read free memory after the load and subtract the weights again). The prompt is counted with the model's tokenizer instead of UTF-8 bytes / 4. A prompt that does not fit at all is 413 before generation. The orchestrator's default ceiling is 65536, the `serve` default, so `basalt harness` is no longer held to 4096. The cloud fallback's memory reason uses the same KV room.

### Hybrid local ↔ cloud
- `serve --cloud-fallback MODEL` (or `cloud_fallback` in `~/.gem/config.json`, switchable with `enabled`, `--no-cloud-fallback`) answers from a model on any OpenAI-compatible server (`--cloud-base-url`, default OpenRouter; a self-hosted `/v1` needs no key) when the local model cannot: the request's KV exceeds 80% of free memory, the prompt exceeds `--local-context-limit`, or the cost router rates the task beyond the local model. The arbiter takes `argmax [w_cap·Φ·(1−δ) − w_lat·τ/τ_max − w_cost·C/B_rem]` under `M_req ≤ η·M_free` and `C ≤ B_rem`; over budget the cloud is not called. Tool and `response_format` requests and service requests stay local; a cloud call that fails to start is answered locally, one that drops mid-stream ends with finish reason `error`, reported as truncated (#22).
- Cost routing in `serve` (#34): `--router-params` loads trained Bradley–Terry parameters and enables the capability reason, tuned by `--cost-threshold` and `--cache-stickiness`; sessions are told apart by `x-session-id`. `virtual_keys` in `~/.gem/config.json` add API keys with their own `max_budget`; the authenticator tags the request with the key id (a client-sent tag is stripped), and `cloud_fallback.session_budget` caps each session.

### Coding agents
- Tool calling on `/v1/messages` (Claude Code): `tools` (`input_schema`) reach the chat template; `tool_use` / `tool_result` history blocks (string or block `content`, `is_error`) are rendered into the prompt like the Responses API's `function_call` / `function_call_output`; calls come back as `tool_use` blocks with `toolu_…` ids and `stop_reason: "tool_use"`, streamed as `content_block_start {tool_use}`, `input_json_delta`, `content_block_stop` after any thinking or text block (#73).
- Tool calling on `/v1/chat/completions`: `tools` in, assistant `tool_calls` and role `tool` messages rendered into the prompt, `message.tool_calls` / streamed `delta.tool_calls` with `finish_reason: "tool_calls"`. The stream's last chunk now reports `length` when generation hit the cap instead of always `stop` (#73).
- `tool_choice` on all three endpoints: `none` keeps the tools in the prompt (same prefix as the next turn) and rejects every call with `[tool call to X rejected: tool_choice is none]`; a named tool keeps every tool in the prompt and only that one is let through (a name not in `tools` is 400); `any` / `required` are not enforced and behave as `auto` (#42); `parallel_tool_calls: false` / `disable_parallel_tool_use: true` end the generation after the first call (#73).
- `/v1/messages`: tool arguments that are not a JSON object go out as `input: {}` (and `partial_json: "{}"`) with the original text in a visible note (#73).
- A tool call the engine parses for a tool that was not offered (or not the forced one) is no longer passed to the client; it becomes the visible `[tool call to X rejected: …]` note, like an unrepairable call (#73, #53).
- Tool results in the history render as `[Tool result for <name>]`, matched by `tool_use_id` / `tool_call_id` / `call_id`, so parallel results are not attributed by order; images in tool results render as `[image omitted]`. Tool schemas are serialized with sorted keys for a stable prompt prefix (#73).

### Generation settings
- `thinking_budget` (OpenAI chat/completions and Responses, `thinkingBudget` on `/api/v1/generate`; Anthropic `thinking: {type: enabled, budget_tokens}`): after that many reasoning tokens the engine forces the end of thinking through mlx-swift-lm's `applyingThinkingBudget`, with Qwen's published transition ("Considering the limited time by the user, I have to give the solution based on the thinking directly now." + `</think>`) for Qwen-family models, whose `qwen3_5` protocol declares none. The forced text is reasoning, the answer is content. The budget is lowered to fit `max_tokens` minus the transition and an answer reserve of min(512, max_tokens/4); a `max_tokens` that leaves fewer than 64 tokens after that reserve is 400 before a stream opens, unless the request itself switches thinking off (`reasoning_effort` `none`/`off`, or thinking disabled); the server's `--reasoning-effort` default is not known at validation, so a request relying on a `none` default is still checked. Anthropic `budget_tokens` must be at least 1 and below `max_tokens`, else 400. Ignored with thinking off, on models without a reasoning protocol, and (logged) on non-Qwen reasoning models whose protocol declares no transition (#105).
- `top_k`, `presence_penalty` (OpenAI semantics: only generated tokens count, the prompt is not penalised; window 1024 tokens instead of mlx-swift-lm's 20) and `repetition_penalty` on the OpenAI endpoints, `top_k` on `/v1/messages`, `topK` / `presencePenalty` / `repetitionPenalty` on `/api/v1/generate`. Out-of-range values are 400 before a stream opens (#105).
- Behaviour change: a request that does not set `temperature`, `top_p` or `top_k` samples with the model's `generation_config.json` (Qwen3.8: 1.0 / 0.95 / 20), falling back to 0.7 / 0.9 / off; `--top-k` and `--repetition-penalty` still beat the model file (#105).
- LFM2.5 MoE (`lfm2_moe`: LFM2.5-24B-A2B, LFM2.5-8B-A1B) get a Liquid profile: `thinking_budget` now applies to them with the same transition as Qwen (it was silently ignored, so these always-thinking models could not be held to a reasoning budget). `reasoning_effort: none` cannot switch their thinking off; neither the model nor its template has a switch (#113).
- `repetition_penalty` in `generation_config.json` is honoured (LFM2.5-24B-A2B: 1.05); the request and `--repetition-penalty` still win (#113).
- Usage reports reasoning tokens: `completion_tokens_details.reasoning_tokens` on chat (streamed when `stream_options.include_usage` is set), `output_tokens_details.reasoning_tokens` on Responses; always present, `0` when the model did not reason; a forced thinking-budget transition counts as reasoning (#105).
- ARC-AGI benchmark: the test grid is labelled `TEST_IN` instead of `IN`, the hybrid instructions are neutral (find the rule mapping every example IN to its OUT; DSL optional), the last 8 code blocks (from the last written) run newest first, each in its own sandbox child, on the training inputs and the test input; the parent compares the training outputs (the child never sees them), and the first block that reproduces every training OUT gives the answer; otherwise the attempt fails as `train_mismatch` with the best block's `train_pairs_passed`; a grid larger than 30×30 counts as no answer; a reply with code never falls back to a JSON grid in the text (`exec_failed`); `--exec-timeout` is a deadline on every block × grid call, and each block's child gets `--exec-timeout` × grids + 3 s for startup; a block that overruns it, hits the memory or disk limit, or prints an unparsable or oversized result line fails alone and the next block is tried; `--answer-tokens` (default 4000) sets `max_tokens` to `--thinking-budget` plus it unless `--max-tokens` is larger; and `--reasoning-effort`, `--thinking-budget`, `--top-k`, `--presence-penalty` are passed to the server; `--temperature` now defaults to the model's own (#105).

### Sampling
- Per-request `min_p` (`minP` on `/api/v1/generate` and MCP) overrides `--min-p` and the model profile default; `0` turns Min-P off for that request. Validated to 0–1 (#40).
- `dynamic_temperature` (`dynamicTemperature`): entropy-based dynamic temperature (EDT, arXiv:2403.14541), `T = T0·N^(θ/H) + γ·R` with N = 0.8, θ = 1.5, γ = 0.5, clamped to 0.05–2 (a request colder than 0.05 keeps its own temperature as the floor). Confident tokens sample near-greedy; a forming repetition loop raises the temperature. With EDT on, `top_p`/`min_p` still cut the original distribution, not the heated one. Off by default; no effect at temperature 0 (#40).
- `RepetitionGuard` exposes a continuous repetition score in [0, 1] alongside its stop decision (#40).

### Prompt cache
- Prefix KV-cache reuse across conversations: a radix tree keeps the KV cache of recent prompts, one node per shared token run. A request takes the longest stored prefix and prefills only the rest, so the next turn of a conversation, and a second conversation with the same system prompt and tools (a Claude Code subagent, another Codex thread), reuse what is already computed instead of prefilling it again; concurrent requests on one prefix both reuse it. All clients share one tree; `prompt_cache_key`, `metadata.user_id` and `x-session-id` are not needed and are ignored; service requests are never cached. Sliding-window layers such as Gemma 3/4 and `--kv-bits` prefill in full (#56, #32).
- Prefix reuse for hybrid attention/SSM models (Qwen3.5/3.6, Ornith-1.5): the prompt is prefilled in two phases and the recurrent state is snapshotted at the end of the request text, before the chat template's closing tokens; the next turn that extends the text restores the snapshot and prefills only the tail, with `cached_tokens` reporting the restored length. Snapshots count against `--prompt-cache-mb`. Ornith-1.5-9B, 12.6k-token agent prompt: second turn ≈1 s instead of ≈36 s. A reused turn can differ from an uncached one after its first tokens (bf16 drift from a different prefill chunking: restored state ≡ two-phase prefill from scratch bitwise, vs one-phase max |Δlogit| 1.56 with the same top 5). Under the byte budget a snapshot branch is evicted whole, and a growing conversation keeps only its two newest snapshots (the newest to continue from, its parent so an edited or regenerated last message still restores); older ones on a single-child chain are dropped and the chain is merged. A conversation sharing only the system prompt with another still prefills in full (#79).
- `--prompt-cache-mb` (default: half of what Metal's recommended GPU working set leaves after the weights; `0` disables) caps the memory of the tree, counted on the stored prompt tokens only, each shared prefix once. Over budget the least recently used branch is cut from its end, so an idle conversation keeps its head (system prompt and tools) longest; a branch in use by a running request is never evicted; a prompt larger than the budget keeps the longest head that fits (#56, #32).
- The tree also holds at most 4096 branches (leaves) in all; beyond that the least recently used free branch is dropped, a branch in use never (#32).
- Usage reports the tokens actually reused: `prompt_tokens_details.cached_tokens`, `input_tokens_details.cached_tokens`, `cache_read_input_tokens` (see Upgrading for Anthropic `input_tokens`). `cached_tokens` reveals how much of a prompt matched an earlier prompt from any client; see the README before sharing a server (#56, #32).
- `--cache-blend` (opt-in, approximate): CacheBlend non-prefix KV reuse (arXiv:2405.16444). Prompt chunks (split after blank lines) keep their pre-RoPE KV and are reused at any position; the first layer is recomputed for all tokens and only the `--cache-blend-ratio` (default 0.5) most deviating reused tokens on later layers. Six reordered files of 550–900 tokens on Qwen3-4B-4bit, teacher-forced top-1 agreement with a full prefill on 200 positions / time to first token: full prefill 0.995 / 10.9 s, ratio 0.5 0.950 / 6.7 s, ratio 0.15 0.930 / 3.7 s, ratio 0 0.925 / 1.1 s — the paper's 0.15 barely beats no recomputation on this sample, hence 0.5. Chunks end at a blank line in one token or across two newline tokens (SentencePiece); chunks under 16 tokens are recomputed; a prompt is blended only when (1 − ratio) × reused share ≥ 0.2 (the blended forward costs ~1.2× native per recomputed token) and the cache stays within 16 384 tokens, otherwise it takes the native chunked prefill and stores its chunks from that cache; ratio 1 is always native. Llama and Qwen3 dense models only; the prompt-cache budget is split in half with the tree; `cached_tokens` counts only exact prefix-tree tokens, blended ones are logged (#36).
- Removed the unused string-based `MultiSlotConversationCache`, `PromptContextBuilder.extractToolPrefix` / `compactWithToolPrefixProtection` and the orchestrator's working-session tracker; the engine's token-level prefix tree replaces them (#56, #32).

### Fixed
- KV-cache memory is estimated from the model's geometry instead of 2 bytes per token (token budget) and 8 bytes per token (memory check): `2 · layers · kv_heads · head_dim · bytes` per token from `config.json` (`text_config` for VLM wrappers), only full-attention layers growing for hybrid models (Ornith-1.5/Qwen3.5: 8 of 32) plus their fixed SSM state, sliding-window layers capped at the window, Gemma 4 full-attention layers with `global_head_dim` (and `num_global_key_value_heads` when `attention_k_eq_v`) and without the `num_kv_shared_layers` that hold no cache, MLA (DeepSeek V2/V3) as the per-head K and V that MLX caches, Jamba and NemotronH attention layers from `attn_layer_period` / `hybrid_override_pattern`, `--kv-bits` as `bits + 0.5` bits per element (`bits + 1` when `head_dim` is not a multiple of 64 and MLX quantizes in groups of 32); `--kv-bits` does not apply to sliding-window layers. The memory-derived token budget is now computed correctly and subtracts the prompt (Qwen3-4B on 16 GB free: 77.5k instead of 128k); cap = max(--max-tokens, memory budget); the budget can only raise it above --max-tokens (see #85); `serve --dry-run` (which takes `--kv-bits`), `models check` and `fit` (its quantization grid and decode-speed estimate; the RAM column and fit level still count weights only) include the KV cache for every model: Qwen3-4B at 32k tokens needs 4.5 GiB of KV, Ornith-1.5-9B 1.05 GiB. Without a cached config the parameter-count estimate of `fit` is the fallback (#75).
- Non-streaming `/v1/chat/completions` and `/v1/responses` answered 500 to an invalid request (e.g. `temperature` or `min_p` out of range); they now return the error's own status, 400 for a bad field.

## 0.3.0 — 2026-10-19

### Upgrading from 0.2.0
- `basalt serve --host` off loopback now refuses to start without a key: set `BASALT_API_KEY`, pass `--api-key`, or `--auto-generate-key`. Clients send it as `Authorization: Bearer` or `x-api-key`.
- Off loopback the server answers 429 beyond 120 requests per minute; raise it with `--rate-limit N`, turn it off with `--rate-limit 0`.
- Building from source (Homebrew included) needs Xcode 26.4+ (Swift 6.3): mlx-swift now declares swift-tools-version 6.3.
- The config stays in `~/.gem/`. The command is still `basalt`.
- Earlier versions left the last request body in `/tmp/basalt_anthropic_request.json` and `/tmp/basalt_openai_request.json`: delete them.

### Security
- An API key is mandatory when serving off loopback (`BASALT_API_KEY`, `--api-key` or `--auto-generate-key`); the key check runs on every route except health and docs. `~/.gem/config.json` is written owner-only and merged, never overwritten (#28, #48).
- Token-bucket rate limit, 429 with `Retry-After`: on by default off loopback (120 req/min), `--rate-limit N` or `rate_limit` in the config, `0` disables (#19, #57).
- `/v1/messages` and `/v1/chat/completions` no longer write every request body (prompts, code, anything pasted) to world-readable files in `/tmp` (`basalt_anthropic_request.json`, `basalt_openai_request.json`). Delete those files if they exist.

### Coding agents
- OpenAI Responses API (`/v1/responses`) with the event sequence Codex expects, `reasoning.effort`, and tool calling end to end: tool definitions reach the model, tool calls stream back to the client (#27, #52).

- Fixed: with tools in the request, the answer was replaced by its first `{…}` fragment, which mangled every Claude Code reply containing code (#53).
