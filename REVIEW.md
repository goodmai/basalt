# Техническое ревью проекта GemmaServer (Обновлено)

## 1. Текущее состояние и Прогресс
Проект успешно развивается в сторону production-ready решения для локального инференса на Apple Silicon (v0.2.0-rc). Основной архитектурный паттерн с использованием `actor` для оркестрации запросов (`ModelOrchestratorActor`) доказал свою эффективность: он обслуживает как MCP, так и REST транспорты без гонок данных. 

### Успешно внедренные новшества:
1. **Профилирование и Контроль памяти (Epic 2):** Реализован `ContextDegradationProfiler` для замера метрик на разных размерах контекста. Внедрен механизм динамического пересчета доступного размера контекста на основе свободной памяти (через `host_statistics64`), предотвращающий OOM.
2. **CI/CD и Тестирование (Epic 6):** Настроен GitHub Actions пайплайн (`model-tests.yml`) для автоматического прогона тестов и бенчмарков (TTFT, TPS) на M-процессорах при каждом PR. Автоматизирована загрузка `mlx-community/Qwen3.5-4B-4bit` для тестов.
3. **UX Командной строки и Распространение (Epic 7):** Реализовано интерактивное меню выбора модели. Добавлен скрипт `install.sh` и Homebrew формула (`Formula/gemma.rb`), решающие проблему удобной установки (ранее это было точкой роста).
4. **Интеграция Агентов (Epic 9):** Внедрен `AgentCapabilityAnalyzer`, способный парсить документацию агентов (форматы `agents.md`, `gemini.md`) и извлекать спецификации доступных инструментов (Tools) с помощью регулярных выражений и текстового парсинга.

## 2. Архитектурный анализ и Точки роста

### 2.1. Безопасность и Аудит (Epic 8 - CRITICAL)
Проект переходит к фазе релиза v0.2.0, однако критичный **Epic 8 (Security & Dependency Audit)** еще не начат. Необходимо:
*   Провести жесткий аудит `AuthService` (проверить криптостойкость хеширования паролей и механизм хранения JWT).
*   Проверить все зависимости (`mlx-swift`, `hummingbird`, `jwt-kit`) на наличие CVE (например, через OSV API).
*   Обеспечить защиту от CWE-20 (Improper Input Validation) и Path Traversal.

### 2.2. Парсинг форматов агентов (Epic 9)
Текущая реализация `AgentCapabilityAnalyzer` использует регулярные выражения для разбора XML (`<skill>`) и Markdown структур. Это работает для простых форматов, но может стать хрупким по мере усложнения описаний (например, для `claude-skill.md`, который пока возвращает пустой массив). В перспективе стоит рассмотреть использование библиотек вроде `swift-markdown` или встроенного `XMLParser`.
