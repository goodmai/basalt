Базовый URL: `http://127.0.0.1:8080` — **аутентификация не требуется**.

## Безопасность

На loopback любой локальный процесс может обращаться к API без ключа, но веб-страница в вашем браузере — нет:

- **Host.** Будучи привязанным к loopback, сервер отвечает только на запросы, у которых `Host` равен `localhost`, `127.0.0.1` или `[::1]` (любой порт), всё остальное получает 403; это блокирует DNS rebinding, когда домен атакующего начинает разрешаться в 127.0.0.1 и его страница читает ваши ответы. При привязке к конкретному адресу принимается также этот адрес. При привязке к `0.0.0.0`/`::` принимается любой `Host`: в этом режиме API-ключ обязателен.
- **Origin.** Запрос с заголовком `Origin` отклоняется (403), если только это не собственный loopback-origin сервера (`http(s)://localhost|127.0.0.1|[::1]` на том порту, который слушает сервер; отсутствие порта означает 80 для http, 443 для https) или адрес из `--allow-origin` / `allowed_origins` (`scheme://host[:port]`, без пути, без завершающего слэша, без `*`; порты по умолчанию совпадают, поэтому `https://app.example:443` эквивалентно `https://app.example`). Другие локальные порты не считаются доверенными: иначе страница на dev-сервере (`localhost:3000`) или в Jupyter могла бы загружать модели и запускать генерацию, так что такому UI требуется `--allow-origin http://localhost:3000`. Клиенты, не отправляющие `Origin` (curl, SDK, Claude Code, Codex), не затрагиваются.
- **Content-Type.** Каждый `POST` обязан передавать `Content-Type: application/json` (параметр `charset` допустим), иначе 415. `curl -d` без `-H "Content-Type: application/json"` отправляет тип формы и отклоняется.
- **Идентификаторы моделей.** Значения `model` в REST — это идентификаторы репозиториев Hugging Face: `/v1/models/load` принимает только `org/name`; в поле `model` запроса генерации форма пути (начинающаяся с `/`, `.` или `~`, либо содержащая `..`, в том числе скрытая в `claude-local/..--x`; окружающие пробелы игнорируются) даёт 400, тогда как любое другое значение, не являющееся id репозитория (`basalt`, `qwen/qwen3-8b-instruct:free`), считается псевдонимом: отвечает уже загруженная модель и переключения не происходит. Локальные пути остаются доступными для `basalt serve --model-path` и MCP. Неудачная загрузка оставляет текущую модель загруженной, а тела ошибок никогда не содержат путей файловой системы (они пишутся в лог сервера).

## Управление моделями

```bash
# List all locally cached models (OpenAI-compatible format)
curl http://localhost:8080/v1/models

# Currently loaded model + readiness status
curl http://localhost:8080/v1/models/current

# Hot-swap to a different model at runtime (blocks until loaded)
curl -s http://localhost:8080/v1/models/load \
  -H "Content-Type: application/json" \
  -d '{"model": "mlx-community/gemma-4-31b-it-4bit"}'
```

`GET /v1/models` возвращает ID с префиксом `claude-local/`, чтобы автоматический выбор моделей в Claude Code добавлял их в список. Поле `display_name` содержит исходный ID репозитория HuggingFace.

## Сырая генерация

```bash
curl -s http://localhost:8080/api/v1/generate \
  -H "Content-Type: application/json" \
  -d '{"prompt": "Explain quantum entanglement.", "maxTokens": 256}'
```

| Поле | Тип | По умолчанию | Описание |
|---|---|---|---|
| `prompt` | string | обязательно | Входной текст |
| `maxTokens` | int | 8192 | Максимум генерируемых токенов |
| `temperature` | float | модель | Температура сэмплирования (0–2); если не задана, берётся из `generation_config.json` модели, иначе 0.7 |
| `topP` | float | модель | Nucleus sampling (0–1); если не задано, берётся из `generation_config.json`, иначе 0.9 |
| `topK` | int | модель | Оставлять k наиболее вероятных токенов; если не задано, берётся `--top-k`, затем `generation_config.json`, иначе выключено |
| `presencePenalty` | float | выкл. | −2…2, вычитается из каждого токена среди последних 1024 сгенерированных токенов (промпт не штрафуется) |
| `repetitionPenalty` | float | `--repetition-penalty` | (0, 2], мультипликативный штраф на недавние токены |
| `thinkingBudget` | int | выкл. | Токены рассуждений, после которых сервер принудительно завершает размышления (Qwen: "Considering the limited time by the user…" + `</think>`), чтобы ответ поместился в `maxTokens`; понижается так, чтобы уложиться в `maxTokens` за вычетом перехода и резерва ответа min(512, maxTokens/4); значение `maxTokens`, оставляющее меньше 64 токенов после резерва, возвращает 400; игнорируется, если размышления выключены, у модели нет протокола рассуждений или это не-Qwen модель, чей протокол не объявляет переход |
| `minP` | float | сервер | Min-P 0–1: отбрасывать токены ниже `minP × max p`. Переопределяет `--min-p` и профиль модели; `0` отключает |
| `dynamicTemperature` | bool | false | Динамическая температура на основе энтропии (EDT): на каждый токен `T = T0·0.8^(1.5/H) + 0.5·R`, ограничена диапазоном 0.05–2 (более холодный запрос сохраняет собственную температуру как нижний порог; `top_p`/`min_p` обрезают исходное распределение), где `H` — энтропия распределения следующего токена, а `R ∈ [0,1]` — индекс повторения. Почти жадная на уверенных токенах и более тёплая при начале зацикливания. Не действует при `temperature: 0` |
| `speculativeLookup` | bool | `--speculative-lookup` | Спекулятивное декодирование с поиском по промпту для этого запроса: до 16 токенов, скопированных из совпадения n-граммы в промпте или выходе, проверяются за один прямой проход; после отклонённого черновика генерация черновиков ставится на паузу на 1, 2, 4… до 64 токенов. При `serve --speculative-recycling`, если ни одна n-грамма не совпала, формируется черновик до 6 токенов из собственных argmax-преемников модели, зафиксированных дважды подряд (Token Recycling, #38), с собственной паузой. Модели только с вниманием и плотные рекуррентные гибриды (Qwen3.5/Ornith, Nemotron-H: отклонённый черновик восстанавливает рекуррентное состояние и проигрывает принятые токены), модели со скользящим окном (Gemma 4: каждый раунд проверки буферизуется, так что отклонённый черновик никогда не перезаписывает кольцо окна), без `--kv-bits` и только с текстовым входом; рекуррентные гибриды с маршрутизацией экспертов (LFM2.5 MoE) игнорируются. На Gemma 4 26B-A4B (MoE) lookup даёт ускорение 1.97× на правках кода и замедление 3–6% на прозе и рассуждениях |

`/v1/chat/completions`, `/v1/responses` и `/v1/messages` принимают те же два поля как `min_p` и `dynamic_temperature`; MCP-инструмент `gemma_generate` — как `minP` и `dynamicTemperature`. Эндпоинты OpenAI принимают `top_k`, `presence_penalty`, `repetition_penalty` и `thinking_budget`; `/v1/messages` принимает `top_k` и `thinking: {"type": "enabled", "budget_tokens": N}` в качестве бюджета размышлений (1 ≤ N < `max_tokens`, иначе 400). Все три принимают `speculative_lookup` (не-булево значение даёт 400); MCP `gemma_generate` принимает `speculativeLookup` (не-булево значение даёт -32602). Поле usage сообщает `completion_tokens_details.reasoning_tokens` (chat; в потоке с `stream_options.include_usage`) и `output_tokens_details.reasoning_tokens` (Responses): `0`, когда модель не рассуждала, а принудительный переход засчитывается как рассуждение.

## Совместимость с OpenAI

```bash
curl -s http://localhost:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "basalt",
    "messages": [{"role": "user", "content": "Hello"}],
    "stream": true
  }'
```

Поддерживает потоковую передачу SSE, системные промпты и многошаговые диалоги. Передача ID модели HuggingFace в поле `"model"` автоматически запускает горячую замену.

Размышления рассуждающей модели возвращаются как `message.reasoning` (в потоке: `delta.reasoning`), имя, принятое в OpenRouter / Ollama, и тот же текст дублируется в `reasoning_content` — имя, которое читают клиенты vLLM, DeepSeek, llama.cpp и LM Studio. Ходы ассистента, отправленные обратно с любым из этих полей, принимаются; сами размышления обратно в промпт не подставляются.

## Совместимость с Anthropic

```bash
curl -s http://localhost:8080/v1/messages \
  -H "Content-Type: application/json" \
  -d '{
    "model": "basalt",
    "max_tokens": 1024,
    "messages": [{"role": "user", "content": "Hello"}]
  }'
```

Реализует полную последовательность SSE-событий Anthropic (`message_start`, `content_block_start`, `content_block_delta`, `message_stop`). Принимает формат контента как в виде простой строки, так и в виде массива блоков.

Блоки `thinking` несут пустую подпись `signature`: у basalt нет ключа для их подписи. Они корректно проходят туда и обратно через basalt, но настоящий Anthropic API отклоняет диалог, переигрывающий их, поэтому удаляйте их перед отправкой той же истории туда.

**Ограниченный вывод (constrained output).** `response_format` ограничивает ответ после любого блока рассуждений с помощью XGrammar:
- `{"type": "json_object"}` или `{"type": "json_schema", "json_schema": {"schema": …}}`;
- `{"type": "regex", "regex": "[A-Z]{3}-\\d{4}"}`;
- `{"type": "grammar", "grammar": "root ::= …"}` — диалект EBNF/GBNF XGrammar с корневым правилом `root`;
- `{"type": "structural_tag", "format": …}` — JSON структурных тегов XGrammar (`sequence`, `const_string`, `regex`, `json_schema`, `tag`, …).

Поля запроса `guided_regex` и `guided_grammar` из vLLM тоже работают, по одному за раз. MCP-инструмент `generate` принимает `regex` или `grammar`. Исходник размером более 64 KB или не компилируемый в XGrammar возвращает 400 с указанием формата.

**Prefill (предзаполнение ответа ассистента).** Диалог, заканчивающийся сообщением ассистента, продолжает это сообщение вместо ответа на него новым ходом — на `/v1/messages`, `/v1/chat/completions` и `/v1/responses`, как в Anthropic API, `continue_final_message` у vLLM и в llama.cpp. Предыдущие ходы рендерятся до приглашения генерации с выключенными размышлениями, текст ассистента следует за ним незакрытым, а ответ содержит только то, что модель дописала после него: при prefill `{"name":` ответ будет ` "Whiskers", "age": 3}`. С `response_format` или принудительным инструментом prefill служит началом JSON-документа (prefill, с которого схема не может начинаться, даёт 400), а аргументы принудительного инструмента включают его. Prefill, открывающий блок размышлений (`<think>…`), сохраняет запрошенный режим размышлений и продолжает его как рассуждение. Несколько завершающих сообщений ассистента склеиваются в один prefill; пустое отбрасывается; сообщение ассистента с вызовами инструментов по-прежнему считается завершённым ходом. Промпт с изображениями продолжать нельзя (400). Управляющие токены в prefill (`<|im_end|>`, `<|im_start|>`, …) нейтрализуются так же, как и в остальной части диалога, поэтому prefill не может подделать ход; реальными остаются только маркеры размышлений, открывающие и закрывающие его рассуждения, а в шаблоне, который сам уже открывает `<think>` (Ornith, Qwen3.5+), собственный начальный `<think>` из prefill отбрасывается, а не удваивается. При `--cloud-fallback` запрос с prefill всегда остаётся локальным, так как не каждый провайдер продолжает завершающее сообщение ассистента. На Nemotron Nano v2, которая отключает размышления строкой `/no_think` в системном ходе, запрос с prefill рендерит другой системный ход по сравнению с запросом с включёнными размышлениями на той же истории, поэтому они делят только prompt-кэш до этого места.

## Ввод изображений

Модель с поддержкой зрения (Gemma 4, Qwen3.5-VL, … — любая модель, загружаемая MLXVLM) принимает изображения на `/v1/chat/completions`, `/v1/responses`, `/v1/messages` и через MCP-инструмент `generate`:

- **OpenAI:** часть контента `{"type": "image_url", "image_url": {"url": "data:image/png;base64,…"}}` (`/v1/responses`: `{"type": "input_image", "image_url": "data:…"}`).
- **Anthropic:** блок контента `{"type": "image", "source": {"type": "base64", "media_type": "image/png", "data": "…"}}`.
- **MCP:** `images: [{"data": "<base64>", "mime": "image/png"}]` или `[{"path": "/abs/file.png"}]` для файла внутри каталога, указанного через `serve --image-dir <dir>` (можно указывать несколько раз). Путь проверяется после разрешения символических ссылок; без `--image-dir` любой путь отклоняется.

Поддерживаются PNG, JPEG, WebP и HEIC, не более 8 изображений на запрос, 20 MB закодированных байт на изображение и 32 MB на все изображения запроса; любое превышение даёт 400 с указанием лимита. Удалённые URL (`http(s)://` в `image_url`, `source.type: "url"`) отклоняются с кодом 400 — basalt не скачивает их; передавайте изображение как `data:` URI. Изображение, отправленное модели без поддержки зрения, возвращает 400 (`<model> does not take images`), никогда не отбрасывается молча, и запрос с изображениями никогда не уходит в `--cloud-fallback`. Ключом в prompt-кэше служит SHA-256 каждого изображения: одинаковые изображения в том же порядке переиспользуют закэшированный префикс, другие изображения не переиспользуют ничего. Логи сессий записывают дайджесты и размеры в байтах, но никогда байты изображений. Изображения внутри результатов инструментов по-прежнему передаются модели как `[image omitted]`.

## Потоковая передача SSE (нативный API)

```bash
curl -N http://localhost:8080/api/v1/generate/stream \
  -H "Content-Type: application/json" \
  -d '{"prompt": "Hello", "maxTokens": 512}'
```

Каждое событие представляет собой строку `data: {...}`; поток завершается строкой `data: [DONE]`. Сбой в середине потока приходит как `event: error` с `data: {"error": ...}`.

## Телеметрия и Prometheus

- **`GET /api/v1/stats`** возвращает снимок телеметрии в формате JSON.
  - Также содержит `windows`: скользящие окна за последние 1 минуту, 5 минут и 1 час с числом запросов, токенов, p50/p95 времени до первого токена и tok/s, долей попаданий в prompt-кэш и долей принятия черновиков.
  - Также содержит `decisions`: по каждой модели принятия решений — запросы, ответы, отказы (abstentions), эскалации, стоимость облака, задержка и ответы по децилям уверенности.
- При `--experimental-expert-streaming` также содержит `experts`: попадания, промахи, вытеснения и прочитанные байты потокового кэша экспертов, а по каждому MoE-слою — статистику маршрутизации экспертов с момента загрузки (количество, число уникальных, восемь самых частых и их доля).
- При `--telemetry-confidence-every N` каждая N-я генерация записывает потокенную вероятность топ-токена, энтропию и разницу между двумя лучшими токенами (top-two margin). Запросы, явно запрашивающие эти данные, записываются всегда. Поле `confidence` затем подсчитывает генерации по децилям минимальной вероятности топ-токена, средней вероятности и минимального отрыва, а также по полунатовым интервалам (half-nat bin) средней энтропии. Каждый измеренный токен стоит одной синхронизации GPU, поэтому значение по умолчанию 0 измеряет только явно запрошенные случаи.
- **`GET /api/v1/metrics`** возвращает те же данные в текстовом формате OpenMetrics для Prometheus или Grafana.
  - Имена метрик начинаются с `basalt_`. Окно и квантиль выступают лейблами, как и модель принятия решений.
  - Эндпоинт защищён тем же API-ключом сервера, что и остальные эндпоинты: передайте сборщику bearer-токен.

```yaml
scrape_configs:
  - job_name: basalt
    metrics_path: /api/v1/metrics
    authorization: { credentials_file: /etc/prometheus/basalt.token }
    static_configs: [{ targets: ["127.0.0.1:8080"] }]
```

Телеметрия хранит только счётчики, тайминги и гистограммы: никакого текста промптов или ответов (#450).

- **Универсальный конвертер (`/v1/models/convert`, `/v1/models/convert/jobs/{id}`)** — Асинхронное квантование «любой в любой» (`MACaQ`, `FlatQuant`, `LIRQuant`, `SINQ`, `QTIP`, `E8P`, `PV-Tuning`, `QAT STE` + `QuantizationAuditCore`, `#546`, `#623`).
