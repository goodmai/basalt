# Облачные решения с Gemini Decision 1

> Languages: [English](../../cloud-decisions.md) · **Русский** · [中文](../zh/cloud-decisions.md) · [Español](../es/cloud-decisions.md) · [Français](../fr/cloud-decisions.md) · [日本語](../ja/cloud-decisions.md) · [Deutsch](../de/cloud-decisions.md) · [한국어](../ko/cloud-decisions.md) · [Bahasa Indonesia](../id/cloud-decisions.md)

Модель Google `gemini-decision-1` отвечает на вопросы System One (`noul`, `choice`, `score`) за один проход по тексту, изображениям, аудио, видео и PDF. Её сетевой формат совпадает с собственным форматом `/v1/systemone` в basalt, поэтому она работает как облачный этап перед локальной моделью принятия решений:

```bash
export GEMINI_API_KEY=...        # read from the environment, never a flag or a file
basalt serve --decision-model cloud:gemini/gemini-decision-1 --decision-escalate self
```

- Неуверенные ответы (уверенность ниже `--decision-escalate-below`), сбои вызовов и ограничения частоты запросов (rate limits) передаются локальной модели.
- `/v1/systemone` принимает `"media": [{"kind": "image|audio|video|pdf", "mime_type": "...", "data": "<base64>"}]` рядом с `state`. Медиаданные отклоняются, если ни один этап не умеет их читать.
- В файле compose модель указывается как `source: cloud:gemini/gemini-decision-1` с `api_key_env: GEMINI_API_KEY`.
  - Модели Gemini обслуживают только каскады принятия решений.
  - Конвейеры оставляют распознанный текст на этом Mac, если только для этой модели не задано `data: media`. В этом случае сами прикреплённые файлы и их распознанный текст отправляются в Google для принятия решения.
- Стоимость подсчитывается по объёму токенов, возвращаемому API, по тарифу $0.10 за миллион входных токенов и учитывается в бюджетах compose.

## Учитель калибровки

Gemini Decision 1 возвращает откалиброванные вероятности, а не просто метки. По данным Google, эта модель лидирует по калибровке вероятностей. Это делает её идеальным учителем калибровки для локальных моделей принятия решений basalt: прогоните одни и те же состояния через неё и через локальное считывание (readout) и подгоните локальную температуру — или обучите голову OpenJev — по её вероятностям. Тогда уверенность локального решателя будет означать то же самое, что и уверенность облачной модели, а пороги эскалации можно будет перенести без изменений. Интеграция этого механизма в шаг калибровки запланирована в рамках работы над локальным JEV в #423 (J6: чтение калибровки из бандла).
