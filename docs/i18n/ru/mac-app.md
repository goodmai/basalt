# Basalt для Mac

> Languages: [English](../../mac-app.md) · **Русский** · [中文](../zh/mac-app.md) · [Español](../es/mac-app.md) · [Français](../fr/mac-app.md) · [日本語](../ja/mac-app.md) · [Deutsch](../de/mac-app.md)

Нативное приложение для basalt: окно чата и окно Монитора, работающие поверх локального движка, который приложение запускает и контролирует. Архитектура и этапы разработки описаны в #434. Это этап 1.

## Сборка и запуск

```bash
./scripts/bundle_app.swift            # release build, Metal kernels, then .build/Basalt.app, signed ad hoc
open .build/Basalt.app
```

- `--identity "Developer ID Application: …"` подписывает сборку с hardened runtime для распространения.
- `--bin PATH` собирает бандл из уже скомпилированных бинарных файлов.
- `--dry-run` выводит план сборки без выполнения.

Для запуска из каталога сборки без создания бандла укажите путь к движку: `BASALT_HELPER=.build/release/Basalt .build/release/BasaltMac`.

## Как это работает

- **Движок работает как отдельный процесс:** встроенный `basalt serve`, расположенный в `Contents/Helpers`.
  - Приложение запускает его на свободном loopback-порту (`--port 0 --announce-ready`) и передаёт уникальный для каждого запуска токен через `BASALT_API_KEY`.
  - Взаимодействие с движком идёт по тому же REST API, который используют редакторы и скрипты.
- **Сбои:** аварийное завершение движка не приводит к падению приложения. Супервизор перезапускает его через 1 с, затем через 2 с и так далее вплоть до 30 с; после трёх сбоев за минуту перезапуски прекращаются и отображается последний вывод движка.
- **Завершение работы:** при выходе из приложения движок останавливается корректно: сначала SIGINT, а через 10 с — SIGKILL.
- **Повторный запуск:** приложение подхватывает уже работающий движок по файлу его состояния (`~/Library/Application Support/Basalt/engine.json`, права 0600), чтобы не загружать модель заново.
- **Диалоги** сохраняются с помощью SwiftData в `~/Library/Application Support/Basalt/Conversations.store`. Ответ, прерванный сбоем, помечается при восстановлении как остановленный.
- **Модель** задаётся в Настройках (по умолчанию `mlx-community/gemma-4-12B-it-qat-4bit`) и применяется при следующем запуске движка.

## Строка меню и быстрый вопрос
- **Движок запускается вместе с приложением**, а не при открытии окна. Значок в строке меню (куб) присутствует даже тогда, когда все окна закрыты. Он отображает состояние движка и текущую модель, а также предоставляет следующие действия:
  - новый диалог и быстрый вопрос;
  - пять последних диалогов;
  - запуск, перезапуск и остановка движка;
  - Монитор, Настройки и Выход.
- **Быстрый вопрос:** сочетание клавиш ⌥Space открывает плавающую панель поверх любого приложения, включая полноэкранные, не забирая у него фокус.
  - Введите вопрос и нажмите ↩. Ответ выводится в панели в потоковом режиме.
  - ⌘↩ открывает переписку как обычный диалог в главном окне.
  - Esc закрывает панель и отбрасывает переписку. До нажатия ⌘↩ ничего из быстрого вопроса не сохраняется.
  - Горячая клавиша регистрируется через `RegisterEventHotKey`, что не требует разрешений Универсального доступа (Accessibility). Её можно отключить в Настройках; изменение вступит в силу при следующем запуске.
- **Настройки:**
  - Основные: выбор модели, быстрый вопрос и автозапуск при входе в систему (`SMAppService`; работает после подписи приложения и переноса в папку «Программы»).
  - Облачные ключи: переменные окружения, такие как `OPENROUTER_API_KEY`, значения которых хранятся в Связке ключей (сервис `app.basalt.mac`). Движок получает их при следующем запуске для облачных моделей в режиме compose. Приложение никогда не записывает их на диск.
- **Восстановление состояния:** выбранный диалог восстанавливается после перезапуска, как и неотправленный черновик для каждого диалога, хранящийся в user defaults.

## Модели
- **Окно «Модели»** (⌥⌘L или пункт «Модели» в строке меню) отображает модели из кэша Hugging Face (`~/.cache/huggingface/hub`) с указанием их размера и вердикта совместимости с данным Mac по данным `GET /v1/models/preview`.
- **Загрузить** переключает движок на выбранную модель (`POST /v1/models/load`) и делает её стартовой моделью движка. Модель с вердиктом «не помещается» нельзя загрузить из приложения; в окне объясняется причина.
- **Скачать** принимает идентификатор репозитория, например `mlx-community/gemma-4-12B-it-qat-4bit`. Приложение загружает файлы в собственном процессе, показывает прогресс и запоминает незавершённые загрузки. При следующем запуске они докачиваются с недозагруженных файлов. При ошибке загрузки отображается кнопка «Повторить».
- **Удалить** запрашивает подтверждение, затем удаляет каталог модели из кэша. Текущую загруженную модель удалить нельзя.

## Вложения
- **Прикрепляйте** файлы через значок скрепки или перетаскиванием в окно диалога: PDF, изображения (PNG, JPEG, HEIC, TIFF, GIF, WebP) и аудио (WAV, MP3, M4A, AAC, FLAC, CAF) размером до 32 MB каждый.
- **Сообщение с вложениями проходит через `/v1/pipeline`.** Движок считывает документы и изображения с помощью своей OCR-модели (или через Apple Vision при её отсутствии). Аудио транскрибируется речевой моделью или чат-моделью. Затем чат-модель отвечает на сообщение (или выполняет запрос «Summarize the attached files.», если текст сообщения пуст).
- **Распознанный текст сохраняется в диалоге.** Каждое вложение отображается в виде чипа, при раскрытии которого виден считанный движком текст. Последующие сообщения отправляются с этим текстом перед вопросом, чтобы в уточнениях можно было ссылаться на файл.
- **Квитанция** под ответом перечисляет каждый этап конвейера с указанием модели и времени выполнения в миллисекундах.

## Инспектор
- **⌥⌘I** или клик по ответу открывает панель инспектора рядом с диалогом.
- **Диалог:** текущая модель и системный промпт для этого диалога. Он сохраняется вместе с диалогом и отправляется перед каждым сообщением. Пустой промпт очищает его.
- **Ответ:** квитанция выбранного ответа: модель, количество токенов промпта и генерации, время до первого токена, скорость и каждый этап конвейера с моделью и временем в миллисекундах.
- **Вложения:** текст, считанный движком из каждого файла вопроса, постранично.

## Быстрые команды, Службы и Dock
- **Быстрые команды (Shortcuts) и Spotlight:** Ask Basalt, Summarize File, Transcribe Audio и Switch Model реализованы как App Intents. «Быстрые команды» запускают их в фоне с участием приложения. Каждая команда ожидает готовности движка (до трёх минут), а Switch Model отклоняет модель, которая не помещается в память. `scripts/bundle_app.swift` извлекает метаданные намерений в `Contents/Resources/Metadata.appintents` с помощью `appintentsmetadataprocessor`, поскольку SwiftPM этого не делает.
- **Службы:** выделите текст в любом приложении и выберите «Службы» → Ask Basalt. Откроется новый диалог с этим текстом в качестве вопроса.
- **Запуск в один клик по `basalt://` с Hugging Face:** `Basalt.app` регистрирует URL-схему `basalt` (`CFBundleURLTypes`). Переход по ссылке `basalt://run?model=<owner/repo>[&role=chat|mtp|moe-stream|ocr|asr|decide|embed|rerank]` — или нажатие **Run with Basalt** на любой карточке модели [`goodmai`](https://huggingface.co/goodmai) — проверяет идентификатор репозитория Hugging Face, обновляет сохранённый выбор модели, выводит Basalt на передний план и переключает контролируемый движок на эту модель или роль в конвейере.
- **Dock:** перетаскивание PDF, изображения или аудиофайла на иконку в Dock открывает новый диалог с этим вложением.
- **Уведомления:** когда генерация ответа завершается при свернутом или фоновом приложении Basalt, уведомление показывает первые строки ответа. Разрешение запрашивается однократно.

## Compose-системы и облако
- **Настройки → Движок:** запуск одной модели или compose-системы из файла (`basalt serve --compose <file>`). Кнопка «Перезапустить движок с этим» останавливает текущий движок и запускает его с новыми аргументами. Этот выбор также используется при следующем запуске.
- **Подхват зависит от аргументов:** приложение подключается к оставленному работающим движку только в том случае, если он был запущен с теми же аргументами. При смене модели или compose-файла запускается новый экземпляр движка. Выход из приложения останавливает в том числе и подхваченный движок.
- **Монитор:** для compose-системы отображает её название, конвейеры и расходы на облако за сегодня, а по каждой модели — состояние (`ready`, `loading`, `no-key`, `over-budget` и т. д.), политику удержания в памяти, текущие расходы, лимит и причины отказов. Облачные модели отмечены значком облака.
- **Облачная пометка:** ответ, в котором использовалась облачная модель, содержит пометку «☁︎ cloud» со стоимостью в строке квитанции и в инспекторе. Всё, что не имеет этой пометки, выполнено локально на этом Mac.

## Универсальный доступ, языки и обновления
- **VoiceOver:**
  - У каждого элемента управления без текстовой подписи есть озвучиваемое название: значок в строке меню, отправка, остановка, прикрепление файла, удаление и инспектор.
  - Каждое сообщение зачитывается как единый элемент: «Вы: …» или «Basalt: …».
  - Индикаторы прогресса озвучивают, чего именно ожидает программа.
  - Индикатор совместимости сообщает «fits on this Mac» (помещается на этом Mac) или «does not fit» (не помещается).
  - Ожидающие отправки вложения зачитываются как «Удалить <файл>» («Remove <file>»).
- **Языки:** приложение использует язык системы. Сейчас поставляются английская и русская локализации. Перевод хранится в `Localization/<language>.lproj/Localizable.strings`, который `scripts/bundle_app.swift` копирует в бандл и перечисляет в `CFBundleLocalizations`. Тест завершается ошибкой, если в интерфейсе появляется строка, отсутствующая в русской таблице локализации.
- **Обновления:** раз в день приложение запрашивает у GitHub API последний релиз basalt. Если доступна более новая стабильная версия (не draft и не pre-release), в строке меню появляется пункт «Доступно обновление» («Update available») со ссылкой на страницу релиза. Запрос не отправляет на GitHub ничего, кроме IP-адреса и User-Agent приложения. Проверку можно отключить в разделе «Настройки → Основные».

## Распространение: подпись, нотаризация и Homebrew cask
- **Локально:** `./scripts/bundle_app.swift --identity "Developer ID Application: Name (TEAMID)" --notarize basalt-notary --dmg` подписывает приложение с hardened runtime и создаёт `Basalt-<version>.zip`. Далее скрипт отправляет архив через `notarytool`, прикрепляет (staple) тикет к приложению, перепаковывает zip и создаёт образ `.dmg`.
  - Флаг `--zip` выполняет упаковку без нотаризации.
  - Флаг `--notarize` отклоняет сборку с ad-hoc-подписью или без подписи.
  - Создайте профиль в Связке ключей один раз командой `xcrun notarytool store-credentials basalt-notary --apple-id <id> --team-id <TEAMID> --password <app-specific password>`.
- **В релизе:** если в репозитории заданы секреты `MAC_SIGNING_IDENTITY` (имя сертификата в Связке ключей раннера) и `MAC_NOTARY_PROFILE` (профиль в Связке ключей), то тег `v*` собирает, подписывает и нотаризует приложение.
  - Сборка прикрепляет `Basalt-<version>.zip` к релизу GitHub.
  - Скрипт генерирует `Casks/basalt-app.rb` из `Casks/basalt-app.rb.template` в том же PR, который обновляет формулу.
  - При отсутствии секретов релиз публикует только формулу с соответствующим уведомлением.
- **Установка:** когда релиз содержит приложение, выполните `brew install --cask goodmai/basalt/basalt-app`.

## Compose Video Studio, универсальный конвертер и Live Hub (`v0.12`)
- **Compose Video Studio:** поэтапная генерация видео в 24 GB UMA и встроенное воспроизведение (`LTX-2.5 AV-DiT`, `Kandinsky 6.0`, `LingBot-Video`, `Wan 2.2`) с экспортом в `.mp4` (`#611`).
- **Универсальный конвертер (`ConvertModelSheet`):** полноценный интерфейс квантования «любой формат в любой» (`MACaQ` dense/MoE, `FlatQuant`, `LIRQuant`, `SINQ`, `QTIP`, `E8P`, `PV-Tuning`, `QAT STE` + `QuantizationAuditCore`) на английском и русском языках (`#546`, `#599`, `#623`).
- **Live Hub и телеметрия SSE с частотой 10 Hz:** реализовано на базе `swift-huggingface` с загрузками Xet, поиском и публикацией в реальном времени на Hub, а также потоковой телеметрией 10 Hz в Мониторе (`#587`).

## Бюджеты производительности
Замеры выполнены на M4 Pro с 24 GB на коммите 530aa28 с моделью Gemma 4 12B в движке (#434):

| Бюджет | Замерено | Лимит | Как измерить |
|---|---|---|---|
| Открытие окна при тёплом запуске | 257 ms медиана по 5 (холодный: 1.6 s) | 400 ms | `swift scripts/app_budgets.swift` |
| Пробуждения в простое после запуска движка | 0 за 10 s | 0 | то же |
| Процесс приложения | 40 MB, плюс 33.5 MB для открытого диалога из 2,000 сообщений | 150 MB | то же и `AppBudgetTests` |
| Потоковый вывод токена в диалог из 2,000 сообщений | 7.4 ms p95, 6.0 ms медиана | 16.7 ms (60 fps) | `BASALT_APP_BUDGETS=1 swift test --filter AppBudgetTests` |
| Быстрый вопрос: панель и первый токен сверх собственного времени движка | 40 ms тёплый (панель 15 ms); первое представление SwiftUI в процессе 175 ms | 150 ms | то же |

Скрипт `app_budgets.swift` захватывает блокировку GPU, так как движок загружает модель. Запускайте оба замера на спокойном Mac без параллельных задач CI. Следующие сценарии требуют ручной проверки, так как не автоматизированы: отображение панели поверх полноэкранного приложения (это неактивирующая панель с `.fullScreenAuxiliary`), запуск App Intents из «Быстрых команд» при закрытом приложении и установка через cask на чистый Mac (для которой требуются секреты подписи).
