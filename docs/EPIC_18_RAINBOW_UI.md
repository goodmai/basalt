# Epic 18: Rainbow AI Chat UI (Metal-Accelerated Interface)

**Платформа:** macOS 14+ / iOS 17+  
**Язык программирования:** Swift 6  
**Графический API:** Metal 3  
**Целевая частота кадров:** 60 FPS (адаптивная синхронизация при ProMotion)  
**Назначение:** Создание высокопроизводительного, полностью кастомного пользовательского интерфейса для взаимодействия с AI-ассистентом, визуально вдохновлённого интерфейсом командной строки Claude Code.  

Ключевая особенность – **радужное оформление** (rainbow UI) с анимированными цветовыми переходами, встроенное непосредственно в шейдеры Metal.

> [!WARNING]
> Архитектура рендеринга и обработки событий для этого Эпика переработана в рамках **[Эпика 20: MVI Event-Driven Architecture](EPIC_20_MVI_EVENT_DRIVEN_ARCHITECTURE.md)** для решения проблем блокировки потоков (MainThread starvation) и фризов инференса MLX.

## 1. Цели и задачи

1. **Metal-рендеринг:** Разработать полностью Metal-ориентированный рендеринг UI без использования UIKit/SwiftUI для основных элементов (окно-контейнер на базе `MTKView`).
2. **Радужный стиль:** Реализовать анимированное радужное оформление фона, текстовых элементов и плейсхолдеров с возможностью смены режимов (idle, ввод, отправка, получение ответа, ошибка).
3. **Трехзонная архитектура:**
   - **Header** – статус, модель AI, индикатор активности.
   - **Center** – скроллируемая история диалога.
   - **Footer** – поле ввода с промпт-символом и динамическими плейсхолдерами.
4. **Существующий функционал рендеринга:** Перенос и адаптация существующего функционала (отрисовка картинок, блоков кода с подсветкой синтаксиса, и диффов изменений) в новый Metal-конвейер.
5. **Агентное тестирование:** Подготовка UI к автоматизированному тестированию AI-агентами за счет интеграции специальных структурных маркеров и метаданных.

## 2. Функциональные требования

### 2.1. Компоновка экрана
- **Header (~40pt):** Содержит название ассистента и статус. Фон может иметь полупрозрачный градиент с радужным оттенком.
- **Center:** Вертикальный список сообщений. Скроллинг через программную прокрутку с инерцией.
- **Footer (~50pt):** 
  - **Постоянный префикс-промпт** (`>` или `❯`) с радужной анимацией.
  - **Динамический плейсхолдер** (виден при пустом поле ввода).
  - **Текстовый курсор** (мигающая черта или блок).

### 2.2. Режимы работы и смена плейсхолдеров

| Режим | Цветовая схема плейсхолдеров | Текст динамического плейсхолдера |
|-------|------------------------------|----------------------------------|
| **IDLE** | Медленное переливание всех цветов радуги | «Введите ваш запрос…» |
| **PROCESSING** | Ускоренная радужная анимация, мерцание | «Генерирую ответ…» |
| **STREAMING** | Радужные волны, пробегающие по тексту | «Печатаю…» |
| **ERROR** | Пульсация красных и оранжевых оттенков | «Ошибка соединения» |
| **FINISHED** | Плавное затухание радуги до спокойного тона | «Готово. Спросите ещё» |

### 2.3. Интеграция существующего функционала рендеринга
Центральная область чата должна поддерживать богатый медиа-контент через интеграцию следующих компонентов в Metal-конвейер:
- **Отрисовка изображений:** Декодирование изображений в текстуры Metal и рендеринг их в виде прямоугольников с закругленными краями (`cornerRadius` через фрагментный шейдер).
- **Блоки кода:** Рендеринг выделенных фоном блоков с моноширинным шрифтом. Подсветка синтаксиса переводится в атрибуты вершин/текстуры для окрашивания слов.
- **Отрисовка диффов (Diffs):** Визуальное отображение добавленных (зеленый фон) и удаленных (красный фон) строк.

### 2.4. Rainbow UI (радужный стиль)
- Декоративные элементы используют анимированный градиент во фрагментном шейдере Metal: `fract(pos.x * scale + time)`.
- Для текста (заголовки, сообщения) радужный эффект применяется выборочно.

## 3. Нефункциональные требования

- **Производительность:** Стабильные 60 FPS, минимальное энергопотребление в режиме idle.
- **Отзывчивость:** Задержка ввода < 8 мс.
- **Плавность:** Двойная буферизация.
- **Swift 6 Concurrency:** Строгое использование акторов (`UIStateActor`, `AIServiceActor`).

## 4. Архитектура Metal-рендеринга

### 4.1. Шейдеры
**Фрагментный шейдер для радужного фона:**
```metal
fragment float4 fragment_rainbow(VertexOut in [[stage_in]], constant Uniforms &uniforms [[buffer(0)]]) {
    float hue = fract(in.uv.x * 5.0 + uniforms.time * 0.2);
    float3 rgb = hsl2rgb(hue, 0.8, 0.6);
    return float4(rgb, 1.0);
}
```

### 4.2. Рендеринг текста и медиа
- Использование `CoreText` для создания атласа глифов.
- Отрисовка картинок происходит как отдельный pass или с использованием специализированного шейдера для текстурированных quad-ов.

## 5. Тестирование (Агентное тестирование)

Поскольку интерфейс отрисовывается на Metal (без нативных `NSView`/`UIView`), классические инструменты Accessibility (VoiceOver, XCUITest) из коробки "не видят" элементы. 

Для того чтобы **AI-агенты могли тестировать этот UI агентно**, вводятся **невидимые семантические маркеры (Markers)**:
- **Metal Accessibility Tree:** Создание параллельного невидимого дерева `NSAccessibilityElement` (macOS), которое синхронизируется с Metal-рендерером. 
- Каждая зона (Header, Footer, InputField) и каждое сообщение в чате обязаны регистрировать свой bounding box и текущий текст/статус в этом дереве.
- **Debug Markers:** В отладочных сборках рендерер может выводить метаданные прямо в пиксели (например, кодировать ID элементов в невидимый альфа-канал или отрисовывать микро-qr-коды по углам), чтобы агент, использующий OCR/Vision, мог 100% точно кликать по нужным координатам.
- **Status Log Export:** Актор `UIStateActor` должен вести скрытый лог смены состояний (например, `IDLE -> PROCESSING`), который агент может прочитать через временный файл или stdout для верификации работы UI.
